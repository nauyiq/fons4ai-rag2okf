#### 已关闭问题

1. 外部入口缺少完整声明式校验：`DocumentController` 增加 `@Validated`，路径和分页参数增加约束；`DocumentParseRequest` 对嵌套分块策略使用 `@Valid`、`@NotNull` 和白名单 `@Pattern`。
2. Application 通过 Setter 拼装解析状态：新增 `KbDocumentResult.configureParse` 行为，由实体维护 INIT 阶段解析输入不变量；上传和手动解析应用服务统一调用实体行为。
3. 结果 CAS 目标不唯一：`advanceStage` 与 `commitParsedArtifacts` 增加 `resultKey` 条件，CAS 同时限定 resultKey、documentId、version、stage、deleted，防止同一文档的其他结果版本被误更新。
4. 任务状态更新遗漏逻辑删除边界：任务 CAS 与失败登记均增加 `deleted=false` 条件。
5. 按后续用户决策移除幂等重放：手动解析在权限与策略预检后始终创建独立结果和任务，不查询或复用既有任务。
6. 删除任务表 `idempotency_key` 与复合唯一约束的迁移脚本已生成，等待用户/DBA 执行；迁移完成前 SQL 当前结构快照保持既有事实。
7. 并发重复结果清理未检查影响行数：`removeById` 未命中时按过期输入失败并依赖事务回滚，不静默留下孤立结果。
8. 敏感内部引用可能经实体 `toString` 泄露：对象键、解析/策略/任务快照和投影引用增加 `@ToString.Exclude`。
9. 快照 record 含可变 `Date`：构造与访问均返回防御性副本，恢复快照不可变契约。
