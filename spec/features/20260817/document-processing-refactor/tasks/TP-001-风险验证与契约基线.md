## 4. S2 质量门禁

- 需求追踪：每项实验和契约均关联 AC 与技术设计决策，不能用“代码可运行”替代验收证据。
- DDD-lite：新文档代码遵循用户域/知识库域分层；应用层编排，领域层只保留实体、Mapper 与领域服务，基础设施负责外部技术细节，不新增 `domain/port`。
- 数据与安全：MySQL、MinIO、ES 的事实层级不被实验代码改写；测试凭据只通过安全配置注入；日志、fixture、报告不得包含密钥或真实私密内容。
- 公共代码：新增或实质修改的公共类型、接口、方法、配置、关键字段和复杂分支逐项检查注释；Java 使用显式 import 与简单类名。
- Evidence：失败结果同样保留，不把未验证协议或文件格式描述为已支持能力。

## 5. 风险与回滚

- 风险：模型 Provider 的 OpenAI-compatible 程度不同；样本不足导致格式能力误判；验证骨架被误当作完整生产实现。
- 回滚：本包不切换生产链路、不执行 DDL、不删除旧代码；若新增契约影响现有构建，回退对应新增类、测试与资源即可。实验结论失败时保留 Evidence，并阻塞或收紧后续范围。
- 暂缓项：MinerU URL/API Key/HTTP Client/远端 DTO/轮询或回调及完整流程验收；生产解析、分块、发布和删除实现；均由后续 Task Pack 或独立 Feature 承担。
