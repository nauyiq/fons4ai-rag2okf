> 状态：V4 基线已确认；CR-008/CR-009 模型配置增量待确认

> 关联任务：T002

## 1. 设计对象与目标

- 具体产品：Rag2OKF，面向个人知识管理者和企业知识管理员的知识加工工作台。
- 本轮任务：补齐此前 V4 尚未覆盖的产品级页面，使登录、注册、知识库、文档、个人中心和设置形成连续体验。
- 页面归属：所有页面均由 Rag2OKF 自有前端提供；邮箱账号、密码和会话属于 Rag2OKF 自身，底层复用 Fons4Cloud 独立 Sa-Token 能力。
- 交付边界：本轮只提供可评审原型和交互说明，不实现真实认证、上传、解析或配置保存。

## 3. 标志性设计

“证据脉络轨道”是本产品唯一重点视觉：

- 登录页显示文件 → 解析 → 分块 → 发布 → OKF 的连续加工轨迹；
- 应用左侧品牌轨道以五个节点表示知识加工主阶段；
- 文档详情使用同一语义展示当前文件的真实处理位置；
- 动效只用于轨道节点进入和当前阶段呼吸，不在普通卡片散落动画；
- 开启 `prefers-reduced-motion` 时取消位移和呼吸动画。

这项设计直接来自 Rag2OKF 的核心价值，不使用泛化的统计大屏或无业务含义的装饰图表。

## 4. 页面范围

| 页面 | 核心任务 | 关键状态 |
| --- | --- | --- |
| 登录页 | 使用邮箱和密码进入 Rag2OKF | 默认、提交中、邮箱或密码错误、尝试过多、登录成功 |
| 注册页 | 使用邮箱和密码创建本地账号并进入个人知识空间 | 邮箱格式非法或不可用、弱密码、两次密码不一致、请求过多、注册成功 |
| 知识库主页 | 查看和创建有权限的知识库 | 正常、空状态、筛选、权限差异 |
| 文档管理 | 上传、查看当前处理状态、进入详情 | 未解析、排队、解析中、待发布、已发布、失败 |
| 文档详情 | 查看当前文件、处理轨迹、解析/分块预览 | 当前状态、失败原因、重新分块确认 |
| 个人中心 | 维护本地展示资料和偏好 | 只显示本地业务字段 |
| 分层设置 | 区分个人、知识库和模型设置 | 默认分块习惯、知识库策略、Provider 连接与模型档案 |

## 5. 页面关键规则

### 5.1 登录

- 页面使用 Rag2OKF 品牌，不出现 Sa-Token 或其他底层框架说明。
- 登录表单使用“邮箱”和“密码”，错误统一为“邮箱或密码不正确”，不暴露邮箱是否已经注册。
- 可提供“保持登录”，其含义是延长安全会话，不展示或保存 token。
- 登录尝试过多时明确说明稍后重试，不暴露内部阈值。
- P0 不提供尚无后端能力的“忘记密码”入口。

### 5.2 注册

- P0 采用邮箱 + 密码 + 确认密码 + 展示名称注册，不采集手机号或短信验证码。
- 邮箱输入使用邮箱键盘与格式校验，系统 trim 后整体转小写，最大 254 字符；密码为 8～64 位且不能与邮箱相同。
- 密码输入提供可见性切换和实时规则提示，但不得在页面持久化或自动回填确认密码。
- 注册成功后原子建立本地账号、个人 Workspace 和管理员成员关系，再建立会话。
- 邮箱格式非法或不可用于注册、弱密码、两次密码不一致和请求过多均在字段附近反馈；失败不跳转，也不确认该邮箱属于某个既有用户。
- 注册页明确提示“邮箱仅用于登录，暂不发送验证邮件”；P0 不显示“已验证”徽标，不暗示系统已确认邮箱所有权。
- 页面只使用面向用户的语言，不展示 Sa-Token、密码摘要、Redis 等技术名词。

### 5.3 知识库与文档

- OKF 仍位于某个知识库内部，不作为独立一级业务入口。
- 普通上传同名文件仍创建新文档，不提示自动合并。
- 页面只显示“当前文件”，不出现版本号、版本列表和回退。
- 重新分块使用 danger Modal，主动作固定为“删除并重新生成分块”。

### 5.4 个人中心与设置

- 个人中心只向当前本人显示完整登录邮箱只读值、头像、展示名、最近登录和本地偏好；列表、日志和非本人上下文对邮箱脱敏。
- 不展示密码、密码摘要、token 或内部安全字段；P0 不提供密码修改入口。
- 不展示邮箱验证状态，也不提供依赖邮箱所有权的密码找回或安全通知入口。
- 设置分为：
  - 个人偏好：主题、默认进入的工作空间、默认分块习惯；
  - 知识库设置：自动解析、自动发布、Parser/Chunk Profile；
  - 模型设置：当前用户的 Provider 连接、文本/向量化模型档案、连接测试和 API Key 替换；
  - 知识库模型：在知识库设置中按“回答生成”“向量化”等用途绑定本人可用的模型档案，页面不展示 API Key。

### 5.5 模型设置增量

模型设置采用“连接在左、模型档案在右”的主从布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 模型设置                                      ＋ 添加连接     │
│ 管理你自己的模型账户；调用费用由对应厂商账户承担              │
├──────────────────────┬───────────────────────────────────────┤
│ Provider 连接        │ 当前连接：阿里云百炼                   │
│ ● 阿里云百炼         │ Base URL  https://...                  │
│ ○ 火山方舟           │ API Key  已配置 ····7K2M  [替换]      │
│ ○ 自定义             │ 最近测试  成功  2 分钟前               │
│                      ├───────────────────────────────────────┤
│                      │ 模型档案                               │
│                      │ 文本模型      qwen-plus      已验证     │
│                      │ 向量化模型    text-embedding-v3 待测试 │
└──────────────────────┴───────────────────────────────────────┘
```

- “添加连接”先选择阿里云百炼、火山方舟、腾讯混元、智谱 BigModel 或 OpenAI-compatible 自定义模板，再进入表单。
- 模板预填厂商和常见 Base URL，不自动填模型名；用户可以根据地域或专属 Workspace 修改 Base URL。
- API Key 只在新建和“替换 Key”弹窗中出现；保存后固定显示“已配置”、掩码和更新时间，不提供显示原值按钮。
- 文本模型与向量化模型分别创建档案，字段包含档案名称、厂商模型名称、可选维度和受控参数。
- “测试模型”按钮附近显示“会向模型厂商发送固定测试文本，可能产生少量费用”；测试结果使用成功、认证失败、地址不可用、模型不存在或能力不匹配等用户语言。
- 知识库设置使用“模型用途绑定”分组：P0 展示“回答生成”和“向量化”两行，每行选择一个兼容档案；后续增加重排、文档理解或 OKF 提取时追加用途行，不改变知识库基础表单结构。
- 每个用途选择框只展示“档案名 / 厂商 / 模型名 / 最近测试状态”，不展示 Base URL 全路径或 API Key；不兼容该用途的模型档案不可选并说明原因。
- 配置缺失或停用时，相关操作显示“请先完成模型设置”，不偷偷切换到系统默认模型。
- 自定义 Base URL 被安全策略拒绝时说明“该地址不符合服务端出站安全策略”，不暴露 IP 解析和内网判断细节。

## 6. 响应式与可访问性

- 桌面原型基准：1600 × 1000。
- 低于 1180px 时收窄左侧面板，表格保留水平滚动。
- 低于 760px 时侧栏折叠为底部/抽屉导航，双栏内容改为单栏。
- 所有状态使用图标/形状/文字，不以颜色作为唯一信息。
- 主要交互具有可见 `:focus-visible` 状态。
- 亮暗主题保持同一信息层级和状态语义。

## 7. 原型评审 Gate

需要用户确认：

1. 登录和注册页是否符合“Rag2OKF 自有产品”定位，且没有内部认证技术说明；
2. 邮箱 + 密码 + 确认密码注册且暂不发送验证邮件，是否适合作为 P0 注册方式；
3. 应用外壳是否延续已确认 V4，而不是另起一套后台模板；
4. 文档列表是否清楚展示当前文件、处理轨迹、解析和发布状态；
5. OKF 是否明确归属于当前知识库；
6. 个人、知识库、平台设置的分层是否合理；
7. 模型设置的 Provider 主从布局、模板选择、API Key 替换与知识库模型选择是否合理。
7. 文档详情是否正确隐藏版本概念；
8. 亮色和暗色主题是否都达到期望的现代感。
