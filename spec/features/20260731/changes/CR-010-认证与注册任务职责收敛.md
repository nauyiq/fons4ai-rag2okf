# CR-010 认证与注册任务职责收敛

> 功能标识：`knowledge-base-document-lifecycle`
> 变更类型：纯文档修正
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-08-03

## 1. 变更摘要

- 变更一句话说明：将登录与工作空间授权基础能力收敛到 T006，将注册、个人 Workspace 开通和注册后登录收敛到 T027，消除两个任务对同一注册行为的重复归属。
- 本次变更结论：T006 不再实现注册接口或创建账号、个人 Workspace、管理员成员关系；T027 作为这些行为及其原子事务的唯一实现任务。
- 是否建议新建 feature：否。本次只修正同一 S2 功能内未实现任务的职责边界，不改变用户可见能力、数据结构或 HTTP 契约。

## 2. 变更原因

- 用户诉求：用户确认按推荐方案继续执行。
- 业务或技术背景：T006 的验收映射包含 AC-031、AC-032，而后续 T027 已专门承担注册接口、注册应用服务、注册页面及账号/Workspace/Member 原子开通，造成重复实现风险。
- 不变更的影响：T006 与 T027 可能分别实现注册编排或事务，导致账号开通、频控、会话建立与测试责任不唯一。

## 3. 当前状态检查

- 任务规划未完成项：T006、T027 均未开始；本 CR 只收敛二者边界，不删除任务。
- 历史 CR 未完成项：CR-004、CR-005 的本地邮箱密码和 Sa-Token 决策继续有效。
- 文档与代码一致性：认证与注册业务代码尚未实现；现有 14 表初始化结构已由用户重建并通过只读 MCP 复核，本 CR 不改变其结构。
- 技术设计与当前实现一致性：接口与安全决策保持不变；仅任务级归属调整。
- 前置条件：用户已明确确认本次职责收敛方案。

## 4. 影响范围

- 需求影响：无。REQ、业务规则及 AC 内容均不变。
- 技术设计影响：无。`POST /auth/session`、`POST /auth/registration`、`GET/PATCH /users/me` 的契约和安全边界不变。
- 代码影响：无即时代码变更；后续 T006 仅实现登录、会话、授权、当前用户资料与工作空间访问基础能力，T027 独占注册开通编排。
- 测试影响：T006 覆盖登录、注销、会话、权限和资料白名单；T027 覆盖注册格式/密码规则、频控、事务回滚、原子开通和注册后登录。
- 接口/契约影响：无。
- 权限/安全影响：职责更清晰；注册事务和会话建立只在 T027 实现，避免双入口产生不一致的安全处理。
- 兼容/回滚影响：实现尚未开始；如需撤销，只需恢复原任务职责文字，不涉及数据迁移或运行态兼容。
- UI 设计确认：T002 UI Gate 已由用户确认通过；本 CR 不改动登录页或注册页的信息架构、布局和交互，只明确其后端任务归属。

- 领域对象/业务规则影响：不适用，原因是本地用户、成员关系、Workspace 和密码规则不变，只调整实现任务归属。
- 状态流转影响：不适用，原因是注册后建立会话、登录、注销和禁用账号的既定状态语义不变。

## 8. 回归与回滚

- 回归风险：若 T006 误实现注册，或 T027 再次创建并行开通逻辑，会破坏本 CR 的单一职责边界。
- 回归验证范围：T006/T027 代码评审应确认注册路由及账号/Workspace/Member 创建仅从 T027 进入；认证错误、频控、会话与本地授权仍保持既有设计语义。
- 回滚方案：任务规划恢复到本 CR 前文本；由于尚无业务代码和数据结构变更，不涉及数据回滚。
- S2 风险门禁：需要。后续仍由 T025、T027、T028、T029 与 T022 关闭认证、安全、隐私和 S2 总门禁。
