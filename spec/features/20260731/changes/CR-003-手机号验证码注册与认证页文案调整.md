# CR-003 手机号验证码注册与认证页文案调整

## 1. 变更摘要

- 变更一句话说明：新增 Rag2OKF 自有手机号验证码注册页和注册 BFF，同时从登录页移除 Fons4Cloud、统一认证等底层实现说明。
- 本次变更结论：P0 注册采用手机号 + 6 位短信验证码，不采集注册密码；注册成功后复用既有本地用户 provisioning 和安全会话流程。
- 是否建议新建 feature：否，注册是现有登录与本地用户体系的标准扩展，不重写知识库核心流程。

## 2. 变更原因

- 用户诉求：需要明确展示文档列表页面；登录页不应提示 Fons4Cloud 统一认证逻辑，并需要新增注册页。
- 业务或技术背景：页面面向最终用户，不应暴露底层认证框架；现有 Fons4Cloud RPC 已支持短信验证码发送及 SMS 模式的注册并认证。
- 不变更的影响：缺少注册入口会造成新用户无法自助进入产品；技术实现文案会破坏 Rag2OKF 独立产品体验并暴露不必要架构信息。

## 4. 影响范围

- 需求影响：新增手机号验证码自助注册、成功 provisioning、失败无副作用和敏感信息规则。
- 技术设计影响：新增注册验证码、注册 BFF、短信频控、Redis key、错误映射和注册页面。
- 代码影响：未来新增 RegistrationController/ApplicationService、身份与验证码 Dubbo adapter、RegistrationRateLimiter 和 RegisterView。
- 测试影响：新增短信发送、频控、验证码、账号复用、本地 provisioning、敏感信息和注册页 E2E。
- 接口/契约影响：新增 `POST /auth/registration-code` 与 `POST /auth/registration`。
- 权限/安全影响：高；涉及手机号、一次性验证码、短信滥用、账号枚举和会话建立。
- 兼容/回滚影响：新增接口不破坏原登录接口；可关闭前端注册入口和服务端 registration endpoints，但不能保留绕过验证码的后门。

## 6. 技术设计影响

- API/RPC/消息影响：
  - `POST /auth/registration-code` 调用 `CommunicationFacadeService.sendAuthSms`；
  - `POST /auth/registration` 调用 `AccountFacadeService.registerAndAuthenticate`，固定 `GrantType.SMS`；
  - clientId/clientSecret 由 BFF 注入，不由前端传递。
- 领域对象/业务规则影响：LocalUser/Workspace 模型不变；新增注册用例，成功后复用 LocalUser 和个人 Workspace 幂等 provisioning。
- 状态流转影响：验证码发送 → 注册并认证 → 本地 provisioning → 会话建立；任一前置失败不得写本地用户、Workspace 或会话。
- 事务/一致性影响：认证账号可能已经成功而本地 provisioning 失败；通过 authAccountId 幂等补建，并在下次成功登录时再次 provisioning。
- 工具包/依赖影响：新增 Infrastructure Communication API/Dubbo 依赖；Redis 增加 cooldown/窗口限流 key。

Redis 目标结构：

| Key | 目的 | TTL | 安全 |
| --- | --- | --- | --- |
| `rag2okf:registration:sms:cooldown:{phoneHash}` | 同一手机号发送间隔 | 60 秒 | phoneHash 使用服务端 salt，不存明文 |
| `rag2okf:registration:sms:daily:{phoneHash}` | 同一手机号每日发送上限 | 最长 24 小时 | 原子计数，不向用户返回内部阈值 |
| `rag2okf:registration:ip:{ipHash}` | 单来源窗口限流 | 10 分钟 | 只存 IP hash |

验证码本体继续由既有身份/通信能力维护，Rag2OKF 不复制验证码数据。

## 8. 回归与回滚

- 回归风险：短信滥用、验证码/手机号泄露、账号枚举、注册成功但本地 provisioning 失败。
- 回归验证范围：RPC adapter、Redis 频控、注册与登录组合、敏感日志、幂等、本地副作用、亮暗主题 E2E。
- 回滚方案：关闭注册入口及两个新增 endpoints；保留登录能力和已建立的合法本地用户，不删除账号或工作空间。
- S2 风险门禁：
  - code/full phone/clientSecret/token 不进入 MySQL、日志和前端持久化；
  - 频控和统一错误响应通过；
  - 注册失败无本地用户/Workspace/会话副作用；
  - 登录/注册页面不出现底层认证技术名词；
  - 用户确认注册页与文档列表原型。
