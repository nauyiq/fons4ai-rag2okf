# CR-012 文档列表与当前文件契约补齐

> 功能标识：`knowledge-base-document-lifecycle`
> 变更类型：契约变更
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-08-05

## 1. 变更摘要

- 变更一句话说明：补齐已设计但未落地的文档分页列表、当前文件并发令牌和最近任务摘要，使 T018 能在刷新后可靠展示并操作当前文档生命周期。
- 本次变更结论：新增 `GET /knowledge-bases/{knowledgeBaseKey}/documents`；文档列表/详情/上传更新响应补充只面向当前文件的 `currentFileToken`、`latestTask` 与 `hasActivePublication`；更新字段使用 `expectedCurrentFileToken`，并将设计中旧的文档更新/下载路径收敛到当前服务的 `/files` 与 `/file`。
- 是否建议新建 feature：否。业务规则、状态机、MySQL/MinIO/ES 结构和版本隐藏边界不变，仅补齐既有设计与当前实现之间的公共契约缺口。

## 2. 变更原因

- 用户诉求：在发现 T018 无法获取文档列表后，要求补充设计和任务并继续执行 T018。
- 代码事实：`DocumentController` 当前没有知识库维度的文档列表接口；`DocumentDetailResponse` 不含当前文件更新令牌或最近任务摘要，前端刷新后无法恢复列表、CAS 更新或状态轮询。
- 设计事实：技术设计 §3.3 已列出文档列表并要求详情包含任务摘要，需求 REQ-005～REQ-012 与 AC-005、AC-009～AC-024 均要求当前文件、异步状态和失败重试可观察。

## 3. 当前状态检查

- 任务规划未完成项：T018 仍未开始；T009、T010、T012、T013、T015、T016 已完成，但其产物未补齐 T018 所需的读取契约。
- 文档与代码一致性：存在差异。技术设计已声明文档列表，代码没有对应 Controller/ApplicationService；设计的 `/content`、`/original` 路径与当前控制器的 `/files`、`/file` 不一致。
- 前置条件：已满足。T002 UI Gate 已通过，用户已明确要求补充设计/任务后执行 T018。

## 4. 影响范围

- 需求影响：无新增或删除需求/AC；明确 REQ-005～REQ-012 的既有可观察性落地方式。
- 技术设计影响：补充文档列表分页、当前文件令牌、最近任务摘要、旧发布保持提示和路由收敛规则。
- 代码影响：新增文档摘要响应、列表查询和批量组装逻辑；扩展现有文档 DTO/更新请求/Controller 契约，并为 T018 提供正式前端读取接口。
- 数据与 DDL 影响：无。只读取既有 `kb_source_document`、`kb_document_version` 与 `kb_processing_task`，不增加表、字段、索引、约束或迁移。
- 测试影响：新增分页隔离、同名文档、当前文件令牌 CAS、最近任务恢复、发布失败保留 active publication 和无版本泄露的应用/Controller 契约测试；T018 增加页面交互测试。
- UI 设计确认：已通过。沿用 T002/V4 的“当前文件 + 处理轨迹”布局；本 CR 不新增版本中心、回退或撤回入口。

- 删除 AC：无。

## 6. 技术设计影响

- 新增文档列表为 `R<PageResponse<DocumentSummaryResponse>>`，只返回当前文件与当前处理/发布事实；使用当前用户成员关系完成知识库授权，按最近更新时间倒序分页。
- `currentFileToken` 是前端不可展示的 CAS token，不包含历史列表语义；更新接口回传 `expectedCurrentFileToken`，服务端内部映射当前不可变文件 version key。
- `latestTask` 只包含安全化任务摘要，用于刷新后轮询和失败重试；`hasActivePublication` 用于在新发布失败或重新分块期间提示旧的已发布内容仍可用。
- 当前 DocumentController 实际路径 `/documents/{documentKey}/files`、`/documents/{documentKey}/file` 作为正式契约收敛目标；不保留双路由兼容层。
- 列表聚合对当前文件和最近任务采用批量查询，避免 N+1；无新依赖。
- 分块预览同时返回 `currentChunkRevisionKey` 作为重新分块的 CAS 令牌；该令牌不表示版本历史，不在 UI 中展示或持久化，仅在用户确认危险操作后随请求提交。

## 7. 数据结构与 DDL 影响

- 是否涉及持久化结构变更：否。
- SQL 当前结构快照：不适用。既有 `kb_source_document.current_document_version_id`、`active_publication_revision_id` 与 `kb_processing_task.source_document_id` 已满足读取条件。
- SQL DDL 动作、执行型变更 DDL 与执行确认：均不适用。

## 8. 回归与回滚

- 回归风险：跨知识库列表越权、更新令牌误暴露为版本功能、列表 N+1、任务摘要泄露 payload/执行信息、发布失败错误地暗示旧内容不可用、现有更新/下载路径漂移。
- 回归验证范围：文档列表和详情的 `R<T>` 契约、USER/ADMIN 授权、CAS 冲突、任务状态/重试、无历史版本字段、上传更新与下载现有路径回归。
- 回滚方案：前后端同版本发布；若需回滚，恢复上一已审核前后端构建。不得临时放开历史版本响应、对象 key、任务 payload 或绕过成员授权。
- S2 风险门禁：T040 与 T018 通过后，仍由 T021/T022 验证跨空间安全、运行态和完整 S2 Evidence Matrix。

## 9. 长期知识影响

- 是否产生长期知识影响：是。
- 影响类型：技术方案、接口契约。
- 影响说明：文档管理的稳定读取模型固定为“当前文件 + 当前状态 + 安全化最近任务摘要”；当前文件令牌只用于 CAS，不构成前端版本功能。
- 处理边界：知识沉淀由用户显式触发 `fons4ai-knowledge-summary` 后处理，本 CR 不生成知识同步任务或知识汇总交接任务。
