# CR-009 知识库模型独立用途绑定调整

> 功能标识：`knowledge-base-document-lifecycle`
> 变更类型：数据结构变更
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-07-31

## 1. 变更摘要

- 变更一句话说明：新增 `kb_model_binding`，将知识库对模型档案的选择从主表固定字段改为按用途维护的独立绑定关系。
- 本次变更结论：`kb_knowledge_base` 不新增 `chat_model_profile_id`、`embedding_model_profile_id`；P0 通过 `ANSWER_GENERATION` 和 `EMBEDDING` 两种用途绑定模型档案，后续可扩展重排、文档理解和 OKF 提取用途。
- 是否建议新建 feature：否。模型配置仍属于既有 CR-008 和知识库设置范围，只调整绑定抽象、数据结构与接口契约。

## 2. 变更原因

- 用户诉求：明确新增独立绑定表，避免模型类型继续固化在知识库表中。
- 技术背景：Rag2OKF 后续会出现 Rerank、多模态视觉理解和 OKF 提取等不同模型用途；固定列会导致每增加用途都修改知识库表和创建/编辑契约。
- 不变更的影响：继续使用固定文本/向量字段会把“模型调用类型”和“知识库业务用途”混在一起，扩展时产生重复 DDL、字段和分支逻辑。

## 3. 当前状态检查

- 任务规划未完成项：T003 候选实现仍只有 11 张表且缺少隔离 MySQL 证据；T031～T036 均未执行。
- 历史 CR 未完成项：CR-008 已规划 Provider、模型档案和两个固定知识库引用；本 CR 仅替代其中“固定知识库引用”部分，Provider、档案、凭证和动态 Client 设计继续有效。
- 文档与代码一致性：当前候选 SQL 和源码均没有模型表或知识库模型字段；设计调整早于实现，不存在需要迁移的业务数据。
- 技术设计与当前实现一致性：T003 候选 SQL 是未验证的 11 表基础；CR-007 的手工初始化 SQL 和 CR-008 的 13 表目标均尚未实现。
- 前置条件：用户已明确确认独立绑定表方向；业务代码、SQL 和原型 HTML 仍需单独实现授权。

## 4. 影响范围

- 需求影响：修改 REQ-018、BR-017、AC-034，新增 BR-022；模型由“固定文本/向量字段”调整为“按用途绑定”。
- 技术设计影响：知识库创建/编辑请求由两个固定 profileKey 改为 `modelBindings[]`；动态解析增加 `usageType` 和用途/模型类型兼容策略。
- 数据影响：新增 `kb_model_binding`，取消 CR-008 原计划加入 `kb_knowledge_base` 的两个模型字段；目标结构从 13 张调整为 14 张。
- 代码影响：实现阶段新增 ModelBinding 领域对象、Repository/Mapper、ModelUsagePolicy 和按用途解析逻辑。
- 测试影响：新增用途唯一、并发更新、所有权、类型兼容、固定字段残留和未来用途扩展契约测试。
- 页面影响：知识库设置按用途渲染模型绑定行，不再把文本模型和向量模型写成知识库固定字段。
- 权限/安全影响：绑定必须同时校验知识库 Workspace 所有权和模型档案 owner；绑定表不得复制 API Key 或 owner 字段。
- 兼容/回滚影响：没有生产结构和数据，不需要迁移；若未来已部署后再调整用途，必须另行处理绑定兼容。

## 5. 需求与 AC 变化

- 新增 AC：无。
- 变更 AC：AC-034 改为验证 `ANSWER_GENERATION` 与 `EMBEDDING` 用途绑定、同用途唯一、所有权和页面安全展示。
- 删除 AC：无。
- REQ/AC 映射调整：REQ-018 继续映射 AC-034、AC-035；BR-022 明确同一知识库同一用途最多一个有效绑定。

## 6. 技术设计影响

- API 影响：
  - 创建/编辑知识库使用 `modelBindings: [{usageType, modelProfileKey}]`。
  - 增加知识库模型绑定 GET/PUT 契约；PUT 按用途整体校验并更新。
- 领域对象影响：新增 `ModelBinding` 和 `ModelUsagePolicy`；KnowledgeBase 不持有具体模型字段。
- 模型兼容：P0 `ANSWER_GENERATION -> CHAT`，`EMBEDDING -> EMBEDDING`；后续启用 `RERANK`、`DOCUMENT_UNDERSTANDING`、`OKF_EXTRACTION` 时必须同时提供模型类型、Client Adapter 和兼容矩阵。
- 动态解析：`UserModelResolver` 先按知识库与 usageType 查唯一 ACTIVE 绑定，再加载档案、连接和凭证；缺失、重复或类型不兼容均 fail-closed。
- UI 设计确认：T032 继续承担模型设置增量 UI Gate，并补充按用途绑定、兼容档案过滤和未来用途扩展表现；T035 在 T032 确认前不得开始。

## 7. 数据结构与 DDL 影响

- 是否涉及持久化结构变更：是，新增独立绑定表并取消两个尚未实现的候选字段。
- 当前结构证据：`fons4ai-rag2okf-service/src/main/resources/db/migration/V1__init_knowledge_engine.sql` 是未完成 T003 的 11 表候选，`kb_knowledge_base` 当前没有模型字段；该脚本未通过隔离 MySQL 验证。
- 目标结构：
  - 新增 `kb_model_binding(binding_key, knowledge_base_id, usage_type, model_profile_id, config_json, status, created, updated, deleted, version)`。
  - UK(`binding_key`)。
  - UK(`knowledge_base_id`,`usage_type`)。
  - IDX(`model_profile_id`,`status`)。
  - IDX(`knowledge_base_id`,`status`)。
  - `kb_knowledge_base` 保持不包含固定模型档案字段。
- 目标结构总数：14 张表。
- SQL 当前结构快照：T005 在隔离 MySQL 验证后同步 `.specify/sql/knowledge_engine/knowledge_document_lifecycle.sql`；当前文件尚不存在。
- 完整初始化 SQL：T031/T033/T037 共同更新 `fons4ai-rag2okf-service/sql/init-schema.sql`，仍保持一个事实来源。
- SQL 交付动作：更新尚未执行的完整初始化 SQL，不生成生产 `ALTER TABLE`；若个人环境已执行旧候选脚本，应重建该未发布环境或另行确认增量脚本。
- DDL 执行方式：真实环境由用户、DBA 或部署流程手工执行；应用启动和 Agent 不执行生产 DDL。
- DDL 闭环：T037 生成目标结构，T004 在隔离 MySQL 确认初始化 SQL 执行状态，T005 同步 SQL 当前结构快照。

## 8. 回归与回滚

- 回归风险：同一用途产生重复有效绑定、用途与模型类型不兼容、绑定跨用户模型档案，或旧固定字段在 DTO/前端残留。
- 回归验证范围：唯一约束、并发原位更新、用途兼容矩阵、两用户越权、档案停用、缺失绑定、固定字段静态扫描和 14 表结构测试。
- 回滚方案：实现发布前可删除 T037 规划并恢复 CR-008 固定字段设计；一旦用户已保存绑定数据，回退固定字段必须另行评审数据转换，不允许静默丢弃非 P0 用途。
- S2 风险门禁：14 表初始化 SQL、隔离 MySQL 实际结构和 SQL 当前结构快照必须一致；动态解析必须只使用唯一有效用途绑定。
