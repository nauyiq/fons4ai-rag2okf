## 1. 变更摘要

- 变更一句话说明：移除 MySQL 抢锁方案，统一使用 Fons4Cloud/Redisson 分布式锁；同时明确 `fons4cloud-auth` 只通过 Dubbo 提供认证，Rag2OKF 自建业务用户、授权、会话和全部业务页面。
- 本次变更结论：MySQL 继续保存任务事实、状态、幂等与崩溃恢复元数据，但不承担跨实例互斥；认证身份与知识库业务用户彻底分层。
- 是否建议新建 feature：否，仍属于现有知识库文档生命周期的并发、安全与页面边界修正。

## 2. 变更原因

- 用户诉求：MySQL 锁过重，要求在入口直接使用 Fons4Cloud 分布式锁；Fons4Cloud 只提供认证服务及 Dubbo 逻辑，知识库有自己的用户体系和页面。
- 技术背景：Fons4Cloud 已提供基于 Redisson 的 `@DistributeLock`、`LockService` 和 watchdog 能力；Auth Service API 已提供 authenticate、refreshToken、revokeToken 等 Dubbo 契约。
- 不变更的影响：
  - 长时间解析若依赖数据库行锁，会放大连接占用、锁等待和多实例调度复杂度；
  - 直接复用认证 authority 会混淆“账号身份”和“知识库业务角色”；
  - 依赖 Fons4Cloud 页面会阻碍 Rag2OKF 形成完整作品级产品体验。

## 6. 技术设计影响

### 6.1 分布式锁

- Scheduler 只普通查询到期候选任务，不使用 `SELECT ... FOR UPDATE`、`SKIP LOCKED` 或数据库行锁抢任务。
- 命令、Worker 和 Outbox 在独立 Spring Bean 的 public 入口使用 Fons4Cloud `@DistributeLock` 或 `LockService`。
- Worker lock key 使用 taskKey，`waitTime=0`；长任务不设置固定 expireTime，交由 Redisson watchdog 续期。
- 未取得锁的实例跳过本轮；取得锁后必须重新读取任务状态并执行状态机校验。
- MySQL heartbeat/executionDeadline 仅用于崩溃恢复和可观察性，不是锁。
- Redis 不可用时写命令和 Worker fail-closed，不得回退到 MySQL 锁。

### 6.2 认证、本地用户与会话

- Rag2OKF BFF 通过 Dubbo 调用 `AccountAuthenticationFacadeService` 的 authenticate、refreshToken、revokeToken。
- clientId/clientSecret 只位于后端密钥配置；浏览器不得提交 clientSecret。
- 认证成功只使用 auth userId/username 最小字段建立本地 `kb_user`，不得整体复制带 password、idCard 等字段的 AccountInfo。
- 浏览器只持有 HttpOnly/Secure/SameSite 的不透明会话 Cookie；access/refresh token 放在有 TTL 的服务端 Redis 会话，不进入 MySQL、日志或前端持久化存储。
- Workspace Member 和 local role 是知识库业务授权唯一来源，认证 authority 不直接映射为管理员。

### 6.3 页面归属

- `fons4ai-rag2okf-ui` 提供登录页、应用外壳、知识库/文档页、个人中心、知识库设置和全局设置页。
- 全局设置 P0 只呈现个人默认分块习惯和模型配置结构占位；未确认的模型和密钥不在本 CR 中启用。
- Fons4Cloud 不提供或承载 Rag2OKF 业务页面。

目标模型调整：

| 对象 | 调整 |
| --- | --- |
| `kb_user` | 新增本地用户、authAccountId 唯一关联、资料、状态、偏好；禁止密码/token/clientSecret/idCard |

## 8. 回归与回滚

- 回归风险：高，主要风险为分布式锁切面因 self-invocation 失效、Redis 故障导致重复执行、远端身份误授业务权限以及 token 泄露。
- 回归验证范围：多实例并发、锁 watchdog、JVM/Redis 故障、任务恢复、Auth Dubbo 契约、本地权限、会话、敏感字段、全页面 E2E。
- 回滚方案：当前仅变更设计与规划，可恢复 CR 前文档；进入实现后不允许以 MySQL 锁或本地密码认证作为降级回滚。
- S2 风险门禁：
  - 锁入口必须经 Spring AOP 代理；
  - MySQL 抢锁语句为零；
  - Auth 身份与本地授权越权测试通过；
  - token/password/clientSecret/idCard 不进入 MySQL、日志和前端持久化；
  - Rag2OKF 全页面 UI Gate 通过。
