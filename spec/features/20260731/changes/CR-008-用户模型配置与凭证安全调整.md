# CR-008 用户模型配置与凭证安全调整

> 功能标识：`knowledge-base-document-lifecycle`
> 变更类型：数据结构变更
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-07-31

## 1. 变更摘要

- 变更一句话说明：Rag2OKF 的文本模型和向量化模型均改为使用当前用户提供的厂商、Base URL、API Key 与模型名称，并允许知识库分别绑定一个文本模型档案和一个向量化模型档案。
- 本次变更结论：新增“用户 Provider 连接 → CHAT/EMBEDDING 模型档案 → 知识库模型引用”三级结构；提供阿里云百炼、火山方舟、腾讯混元、智谱 BigModel 和 OpenAI-compatible 自定义模板。
- 是否建议新建 feature：否。模型设置和知识库设置已在现有需求与 V4 原型范围内，本次是对占位能力的正式契约、数据与安全设计补充。

## 2. 变更原因

- 用户诉求：所有模型必须使用用户设置的配置，模型厂商、Base URL、API Key 和实际模型名称都由用户提供；Rag2OKF 按这组配置访问模型服务，并提供常见厂商模板。
- 业务背景：不同用户可能使用不同厂商、地域、账号和模型配额，系统级固定模型会造成凭证归属、费用、数据流向和租户隔离不清。
- 技术背景：文本生成与向量化具有不同模型名称、能力和可选参数，不能只用一个模糊的“模型配置”对象表达。
- 不变更的影响：继续依赖应用全局模型会使知识库无法证明实际使用哪个用户凭证，也可能在配置错误时误用平台 Key、其他用户配置或错误模型。

## 3. 当前状态检查

- 任务规划状态：T001、T002 已完成；T003 已存在 11 表候选实现，但隔离 MySQL 验证尚未完成；CR-007 追加的 T031 尚未实现。
- 原型状态：V4 基线已由用户确认，模型设置目前只有占位说明；本 CR 追加 T032，先完成模型设置增量原型并取得确认。
- 数据状态：没有已部署的生产数据库、模型配置表或真实厂商凭证；候选初始化 SQL 尚未在确认的 MySQL 环境执行。
- 代码状态：当前后端不存在用户级 Provider 连接、模型档案、凭证加密、出站地址策略或动态模型客户端实现。
- 设计差异：原设计未定义用户模型配置的所有权、知识库绑定、API Key 存储和自定义 Base URL 安全边界，本 CR 已同步需求、技术设计、UI 设计和任务规划。
- 前置条件：需求与技术方案可以完成评审；代码、SQL 和原型 HTML 的改动仍需用户明确授权。

## 4. 影响范围

- 需求影响：新增 REQ-017～REQ-019、BR-017～BR-021、AC-033～AC-036。
- 技术设计影响：新增模型配置 REST 契约、Provider 模板、模型解析流程、动态 LangChain4j Client、API Key 加密和 SSRF 防护。
- 数据影响：新增 `kb_model_connection`、`kb_model_profile`；`kb_knowledge_base` 新增文本模型档案和向量化模型档案引用，目标结构由 11 张表扩展为 13 张表。
- 前端影响：模型设置从占位页调整为 Provider 连接与模型档案主从页面；知识库设置增加两个模型选择项。
- 测试影响：增加 Mock Provider、凭证轮换、跨用户越权、SSRF/DNS/redirect、无全局 fallback 和浏览器零凭证持久化验证。
- 外部系统影响：用户主动测试或后续模型任务会访问其配置的第三方模型服务，并可能产生厂商费用。
- 兼容影响：当前 BM25 发布和 Elasticsearch V1 不使用模型，不因本 CR 改变；文档向量化、混合检索、RAG 问答和 OKF 生成仍需后续独立 SDD。

## 5. 需求与 AC 变化

- 新增需求：
  - REQ-017：当前用户维护自己的 Provider 连接和凭证。
  - REQ-018：当前用户分别维护 CHAT 与 EMBEDDING 模型档案，知识库分别引用。
  - REQ-019：所有模型访问使用绑定档案的 Base URL、API Key 和模型名称，失败时不得静默回退。
- 新增业务规则：BR-017～BR-021，覆盖模板边界、用户所有权、凭证安全、fail-closed 和未来向量模型变更规则。
- 新增验收标准：
  - AC-033：模板/自定义连接保存与实际最小测试。
  - AC-034：文本/向量化档案及知识库绑定。
  - AC-035：缺失、停用、越权或厂商失败时无全局 fallback。
  - AC-036：API Key 加密、只替换、零回显和零前端持久化。
- 删除或放宽的 REQ/AC：无。

## 6. 技术设计影响

- API：新增模板、Provider 连接、模型档案及测试接口；知识库创建/编辑契约新增 `chatModelProfileKey` 和 `embeddingModelProfileKey`。
- 领域对象：新增 `ModelConnection` 和 `ModelProfile`，两者都归属当前用户；知识库只保存档案引用，不复制 Base URL 或凭证。
- 动态调用：应用层按当前用户和知识库解析档案，解密连接凭证，再使用 LangChain4j Builder 创建请求级或受控短生命周期 Client。
- Spring 边界：不把用户模型 Client 注册成跨用户单例 Bean，不使用 `langchain4j.open-ai.*` 构成可运行的平台模型。
- 模板边界：模板只提供厂商、OpenAI-compatible 协议和常见 Base URL；API Key、模型名称、地域可用性、配额和计费均由用户负责确认。
- 测试边界：模型测试发送无业务数据的固定短文本；自动化只使用本地 Mock Provider，真实 Key 不进入源码、配置、测试或报告。

## 7. 数据结构与 DDL 影响

- 是否涉及持久化结构变更：是，属于未部署新系统的目标初始结构扩展。
- 新增表：
  - `kb_model_connection`：用户、厂商、显示名称、Base URL、加密凭证、nonce、key version、状态和审计字段。
  - `kb_model_profile`：连接、模型类型、档案名称、厂商模型名称、可选维度、受控参数、测试状态和审计字段。
- 修改表：`kb_knowledge_base` 新增 `chat_model_profile_id`、`embedding_model_profile_id`。
- 目标结构总数：13 张表。
- SQL 当前结构快照：实现阶段由 T005 同步 `.specify/sql/knowledge_engine/knowledge_document_lifecycle.sql`。
- 执行型完整 SQL：`fons4ai-rag2okf-service/sql/init-schema.sql`，由 T031/T033 共同形成单一事实来源。
- DDL 方式：由于当前没有已部署结构，本轮直接更新完整初始建表 SQL，不生成 `ALTER` 脚本；若某个私有环境已手工执行旧候选结构，应单独确认重建或增量脚本，不得直接套用本结论。
- DDL 执行责任：真实环境由用户、DBA 或部署流程手工执行；应用启动不执行 DDL，Agent 不直接执行生产 DDL。
- 凭证存储：API Key 使用 AES-256-GCM 加密，密文、每记录 nonce 和 key version 分列保存；部署主密钥或 KMS 引用不进入数据库、仓库和前端。

## 8. 回归与回滚

- 回归风险：错误的所有权校验可能跨用户读取配置；错误的地址校验可能造成 SSRF；全局模型配置可能成为隐式 fallback；维度变化可能在未来破坏向量索引兼容。
- 回归验证：两用户隔离、Key 创建/替换/错误版本、日志与响应扫描、IPv4/IPv6 私网、loopback、link-local、redirect、DNS 重绑定、Mock Chat/Embedding 和零全局 fallback。
- 回滚方案：当前没有已部署模型配置数据，可在实现发布前撤销两张新增表、两个引用字段和对应 API；一旦真实用户已保存凭证，删除或回退必须另行评审并先处理凭证和知识库引用。
- 向量兼容：本 CR 不创建 ES 向量字段；未来切换向量化模型或维度时必须通过独立需求执行重新向量化、索引版本和切换验证。

## 9. 长期知识影响

- 是否产生长期知识影响：是。
- 影响类型：技术方案、数据结构、安全与模型治理规则。
- 影响说明：Rag2OKF 不拥有可供业务使用的全局模型；用户连接保存访问边界，模型档案保存能力和模型名，知识库只引用档案；模型调用必须按所有权解析并 fail-closed。
- 处理边界：长期知识沉淀只在用户显式触发 `fons4ai-knowledge-summary` 后执行，本 CR 不自动创建知识汇总任务。
