# CR-014 删除文档版本表、合并文件字段与新增文件夹路径

> 功能标识：`knowledge-base-document-lifecycle`
> 变更类型：数据结构变更 + 契约变更
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-08-06

## 1. 变更摘要

- 变更一句话说明：删除 `kb_document_version` 表，将文件元数据合并到 `kb_source_document`；新增 `folder_path` 字段支持文件夹层级；MinIO 路径从 `versions/{versionKey}/{filename}` 简化为 `documents/{documentKey}/{filename}`。
- 本次变更结论：表数量从 14 张降为 13 张；`kb_source_document` 合并 6 个文件字段 + 1 个 CAS 令牌 + 1 个文件夹路径；`kb_parse_revision` 和 `kb_publication_revision` 删除 `document_version_id`；所有 payload/manifest/ES 投影中的 `versionKey` 改为 `documentKey`；新增文件夹路径和批量上传 API。
- 是否建议新建 feature：否。核心状态机（解析/分块/发布）不变，只是数据载体从独立版本表合并到文档表。

## 2. 变更原因

- 用户决策：不需要不可变版本追溯链路，前端只展示当前文件，版本表是过度设计。
- 用户诉求：知识库内按文件夹组织文档，上传时保留目录结构。
- 简化收益：减少一张表、一个实体、一个 Mapper、一个 DomainService、4 个跨表指针关联；上传/更新/下载链路不再需要 join version 表。

### 3.3 MinIO 存储路径变化

```diff
- workspaces/{wsKey}/knowledge-bases/{kbKey}/documents/{docKey}/versions/{versionKey}/{filename}
+ workspaces/{wsKey}/knowledge-bases/{kbKey}/documents/{docKey}/{filename}
```

去掉 `versions/{versionKey}` 层级。更新文件时上传新对象、删除旧对象。

### 3.4 代码影响

**删除**：
- `KbDocumentVersionEntity`、`KbDocumentVersionMapper`、`KbDocumentVersionDomainService`

**修改 `kb_source_document` 相关**：
- `KbSourceDocumentEntity` - 新增 9 个字段，删除 `currentDocumentVersionId`
- `DocumentApplicationService` - 上传/更新/列表/详情/下载逻辑重写（不再创建 Version 行，直接写 Document）
- `DocumentController` - 上传/列表新增 `folderKey` 参数；响应 DTO 从 version 取值改为从 document 取值

**修改解析链路**：
- `ParseApplicationService` - 从 document 直接取 objectKey/filename/contentType，不再加载 Version
- `ParseTaskPayload` - `documentVersionId`/`versionKey` 改为 `documentKey`
- `ParseTaskExecutor` - 创建 ParseRevision 时不设 documentVersionId
- `Fons4AiDocumentParserAdapter` - `documentVersionKey` 改为 `documentKey`
- `ParseManifest` - `documentVersionKey` 改为 `documentKey`
- `FonsOssDocumentArtifactStore` - `originalObjectKey` 去掉 versionKey 段

**修改发布链路**：
- `PublicationApplicationService` - 从 document 直接取文件信息
- `PublicationTaskPayload` - `documentVersionId`/`versionKey` 改为 `documentKey`
- `PublicationTaskExecutor` - 创建 PublicationRevision 时不设 documentVersionId
- `PublicationManifest` - `documentVersionKey` 改为 `documentKey`
- `ElasticsearchPublicationProjection` - ES 字段 `documentVersionKey` 改为 `documentKey`
- `PublicationProjectionPort.ProjectionRequest` - 同步改名

**重新分块链路**：零改动（不依赖 document_version）。

**新增文件夹与批量上传**：
- `DocumentController` - 新增批量上传端点；上传/列表加 `folderKey` 参数
- `documents.ts` - 新增批量上传 API
- `DocumentsView.vue` - 文件夹树视图、面包屑、批量上传入口

### 3.5 文件更新行为变化

| 行为 | 旧（版本表） | 新（合并到文档表） |
|------|-------------|-------------------|
| 上传文件 | 创建 Version 行 + 设指针 | 直接写 Document 字段 |
| 更新文件 | 创建新 Version 行 + CAS 切换指针 + 清空 parse/chunk | CAS 校验 fileToken + 覆盖 Document 字段 + 删旧 MinIO 对象 + 清空 parse/chunk |
| 下载文件 | 从 Version 取 objectKey | 从 Document 取 objectKey |
| 旧发布保护 | 旧 Version 的 MinIO 对象不删 | 旧 objectKey 存入 PublicationRevision.manifest_object_key，下载走 ES 投影不依赖 MinIO |

### 3.6 回滚与风险

- **兼容**：DDL 草案为全量重建（删表+建表），存量数据需重新初始化。
- **回滚**：回退 init-schema.sql 和代码即可，无生产数据需迁移。
- **风险**：更新文件时需先上传新对象再删旧对象，避免删除失败导致文件丢失。
