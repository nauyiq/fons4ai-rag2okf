# CR-005 邮箱密码登录注册调整

> 功能标识：`knowledge-base-document-lifecycle`
> 变更类型：契约变更
> SDD 等级：`S2`
> 文档状态：正式
> 创建日期：2026-07-31

## 1. 变更摘要

- 变更一句话说明：Rag2OKF 将本地账号的唯一登录标识从用户名调整为邮箱，使用邮箱和密码完成注册与登录，P0 不发送验证邮件。
- 本次变更结论：邮箱经过 trim 和整体小写规范化后全局唯一；注册成功后直接创建个人工作空间和会话；不建立 `email_verified`、`verified_at` 或验证码状态，邮箱不能被视为已核验联系方式或身份证明。
- 是否建议新建 feature：否。知识库文档生命周期、认证主体和 Sa-Token 会话架构不变，只调整现有认证字段、HTTP 契约、安全边界和页面。

## 2. 变更原因

- 用户诉求：采用邮件注册，但不发送邮件认证；使用邮箱和密码登录、注册。
- 业务或技术背景：CR-004 已确认 Rag2OKF 自主维护账号密码并使用 `fons4cloud-auth-satoken` 管理会话，本次只需把可变用户名收敛为邮箱登录标识。
- 不变更的影响：继续保留 username 会使需求、接口、数据结构和用户看到的邮箱表单不一致；误加邮箱验证状态又会暗示系统已经证明邮箱所有权。

- UI 设计确认：V4 登录、注册和个人中心已调整为邮箱语义；T002 UI Gate 仍等待用户确认。

## 4. 影响范围

- 需求影响：REQ-001、REQ-014、REQ-016、BR-013～BR-016、AC-026～AC-029、AC-031、AC-032 的登录标识和隐私语义调整。
- 技术设计影响：HTTP 字段、账号查询、邮箱规范化、MySQL 字段、Redis 频控 key、日志脱敏、异常、安全风险和页面文案调整。
- 代码影响：未来新增 EmailNormalizer；LocalAccountRepository 改为按 email 查找；目标字段由 username 改为 email。
- 测试影响：新增邮箱格式、长度、规范化、大小写唯一、脱敏、零邮件调用和零验证状态测试。
- 接口/契约影响：`POST /auth/session` 与 `POST /auth/registration` 的 username 改为 email；不新增邮件验证码、验证或密码找回接口。
- 权限/安全影响：高。邮箱属于个人数据，但 P0 不证明邮箱所有权，必须避免枚举、日志泄露和能力误用。
- 兼容/回滚影响：当前未实现，不涉及存量用户迁移；实施后若增加邮箱验证，必须另立 CR 并设计验证状态迁移。

## 6. 技术设计影响

- API/RPC/消息影响：
  - `/auth/session` 接收 email/password/rememberMe；
  - `/auth/registration` 接收 email/password/confirmPassword/displayName/termsAccepted；
  - 不新增 email-verification、verification-code、password-reset 或邮件通知接口；
  - 不调用 Communication API、邮件服务或认证 Dubbo。
- 领域对象/业务规则影响：`kb_user.email` 是规范化后全局唯一的登录标识；Sa-Token loginId 仍使用不可变 userKey，Workspace Member 仍是业务角色来源。
- 状态流转影响：注册成功后直接进入 ACTIVE 和已登录状态，不存在待验证、已验证或验证失败状态。
- 事务/一致性影响：规范化邮箱唯一性、本地账号、PERSONAL Workspace 和 ADMIN Member 继续在单个 MySQL 事务内完成；会话在事务提交后建立。
- 工具包/依赖影响：保留 `fons4cloud-auth-satoken`、Spring Security Crypto 和 Common Cache；不新增邮件 SDK、SMTP、验证码或 Communication 依赖。

## 8. 回归与回滚

- 回归风险：大小写重复邮箱、邮箱枚举、完整邮箱进入日志或锁 key、把未验证邮箱误用于找回密码/通知/实名判断、页面错误展示“已验证”。
- 回归验证范围：EmailNormalizer、唯一索引、登录/注册统一错误、邮箱脱敏、依赖树、接口路由、页面文案、个人中心、三主题 E2E。
- 回滚方案：实现前可恢复 CR-004 的 username 设计；实现后不能直接把 email 改回 username，需根据已产生账号数据另立迁移 CR。
- S2 风险门禁：
  - email trim、整体小写、最大 254 字符与格式校验一致；
  - 大小写不同但规范化后相同的邮箱只能创建一个账号；
  - 完整邮箱不进入日志、指标标签、前端持久化或分布式锁 key；
  - 登录错误不暴露邮箱是否注册，注册冲突不确认既有用户身份；
  - 无邮件发送依赖、验证接口、验证字段、验证徽标、密码找回和安全通知；
  - 当前本人可查看只读完整邮箱，其他输出按 `y***@example.com` 形式脱敏。
