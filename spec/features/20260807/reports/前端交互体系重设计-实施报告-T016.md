## 4. 实现核实结论

### 4.1 DELETE 软删除（deleted=1）
- `KnowledgeBaseApplicationService.deleteKnowledgeBase`（L276-291）调用 `knowledgeBaseDomainService.removeById(entity.getId())`。
- `CommonEntity`（`com.fons.cloud.db.entity.CommonEntity`）含 `@TableLogic` 标注的 `deleted` 字段，MyBatis-Plus 的 `removeById` 自动执行软删除（置 deleted=1），不物理删除。

### 4.2 owner_user_id === session.userId 权限校验
- L287：`if (entity.getOwnerUserId() == null || !entity.getOwnerUserId().equals(user.getId()))` 不匹配时抛 `WorkspaceAccessDeniedException`。
- `user.getId()` 来自 `currentUserContext.requireCurrentUser()`，即当前会话用户主键。

### 4.3 不匹配返回 403
- `WorkspaceAccessDeniedException` 继承 `BusinessRuntimeException`，构造时使用 `ResultCode.NOT_PERMISSION`。
- `Rag2OkfExceptionEndpoint`（L63-67）以 `@ResponseStatus(HttpStatus.FORBIDDEN)` + `@ExceptionHandler({WorkspaceAccessDeniedException.class, ModelAccessDeniedException.class})` 收敛为 403 响应。

### 4.4 已删除/不存在幂等返回成功
- `getOne` 查询受 `@TableLogic` 影响，自动过滤已软删除记录（deleted=1 不返回）。
- 已软删除的知识库 → `getOne` 返回 null → L283-285 提前 return，不抛异常，幂等成功。
- 不存在的知识库 → 同样返回 null → 幂等成功。
- 不泄露存在性与删除状态（统一静默返回）。

### 4.5 GET 列表返回 ownerUserKey 与 canDelete
- `toSummaryResponse`（L456-472）返回 `KnowledgeBaseSummaryResponse`，含 `ownerUserKey`（由 owner_user_id 关联 kb_user 得到 userKey）和 `canDelete`。
- `KnowledgeBaseSummaryResponse` 为 Java record，字段齐全。

### 4.6 canDelete 计算逻辑
- L466-467：`canDelete = entity.getOwnerUserId() != null && entity.getOwnerUserId().equals(currentUserId)`。
- 仅创建者（owner_user_id 等于当前会话用户主键）canDelete=true，其余 false。
- `loadOwnerUserMap`（L480-490）批量查询创建者避免 N+1。
