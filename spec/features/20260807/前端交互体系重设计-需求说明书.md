## 一句话说明

对 Rag2OKF 前端进行交互体系级重塑，解决当前导航模型混乱、操作流割裂、反馈不清晰和页面元素简单的问题，参考同类知识库产品的交互范式，让用户在管理知识库、配置模型和处理文档时获得连贯、清晰、信息密度合理的体验。

## 背景与目标

- 背景：Rag2OKF 前端已实现知识库文档生命周期的基础页面，但当前交互方式不友好、页面元素简单、导航模型混乱（左侧轨道与上下文栏职责重叠且多处占位失效）、操作流割裂（配置与操作跨页分离）、反馈不清晰（页面级错误与全局提交锁）、视觉信息密度不合理（卡片内容稀疏、列表用卡片样式模拟）。
- 当前问题：用户完成一个任务需要在多个页面间来回跳转，上下文频繁丢失；操作发生后无法清晰感知发生了什么、下一步该做什么；导航入口与实际能力不一致，失效占位降低信任；页面元素过于简单，无法支撑高效的知识管理操作。
- 目标：参考同类知识库产品的成熟交互范式，重塑 Rag2OKF 前端的导航模型、操作流、反馈体系和视觉密度，让用户在管理知识库、配置模型和处理文档时获得连贯、清晰、信息密度合理的体验。前端先行用演示数据验证交互，满意后再优化后端接口。
- 不做会怎样：继续增加页面会放大交互漂移和重复实现；用户信任和操作效率持续下降；后续 OKF、问答、评测能力缺乏稳定的交互基座。

## 需求范围

### 本次包含

- 导航模型重塑：废弃当前左侧轨道处理阶段语义当导航的模式，改为顶部导航模式（logo 首页、知识库、搜索 disabled、聊天 disabled），导航只展示真实可用能力或明确的不可用状态。
- 知识库列表管理增强：在知识库列表页支持重命名和删除知识库；删除必须二次确认，且仅知识库创建者可执行删除。
- 弹窗模式统一：新增和编辑操作统一使用页面中央弹窗，替代当前右侧抽屉。
- 模型设置简化：将当前的"Provider 连接"与"模型档案"两层结构合并为单一的模型配置概念，用户用一个表单填完所有字段（包括高级参数如上下文窗口长度）；后端数据结构合并变更在后端阶段执行。
- 知识库目录结构管理：将当前"文件夹"重定位为"知识库目录结构管理"，支持在知识库页面右键创建目录、文档列表以树状结构展示目录层级；继续使用前端暂存，不新增后端目录表。
- 操作流与反馈体系：操作反馈归属到触发操作附近，不再使用页面级错误或全局提交锁；文档异步任务刷新优化为局部刷新、按状态启停、避免重叠请求。
- 视觉与信息密度：根据数据特征合理选择卡片、表格或列表模式，提升页面元素丰富度和信息密度。
- 前端先行开发策略：前端优先用演示数据走通交互，提供演示数据与真实接口可切换的机制，交互满意后再设计与优化后端接口。
- 主题与可访问性延续：延续亮色、暗色和跟随系统三主题，保证键盘可访问性和响应式；主题切换入口保留在 topbar 右侧独立按钮，选择缓存到浏览器 localStorage。
- 个人偏好页面清理：移除个人偏好设置页面及其路由，不再支持用户级默认分块大小和默认重叠量配置；主题切换不再依赖后端 preferenceJson。
- 文档详情页源文件预览：点击文档进入详情页直接展示源文件内容（图片/PDF/Markdown/TXT/DOCX 分组件渲染），分块详情右侧并排展示。
- 文档解析交互优化：解析中禁用解析按钮并显示进度条或"解析中"文案；解析失败后允许再次解析。
- 文档删除管理：文档列表页支持单个删除和批量勾选删除，删除二次确认；后端同步删除 RAG 知识（ES 索引）和解析结果，软删除文档记录（后端阶段执行）。

### 本次不包含

- 全局搜索启用（跨知识库或跨文档内容检索）：留给后续 feature。
- 知识库权限控制和用户协作（邀请其他用户加入知识库）：后续实现，本次不纳入。
- OKF 构建、知识问答、评测中心：后续 feature。
- 文档任务完整历史视图（多任务列表）：暂不纳入，可后置。
- 文档内容在线编辑、扫描件人工 OCR 校正。
- 手机号/短信验证码、第三方登录、忘记密码。
- 改变知识库文档生命周期的业务状态机（上传、解析、发布、重新分块的业务规则不变）。

## 角色与场景

| 角色或参与方 | 使用场景 | 触发条件 | 期望结果 |
| --- | --- | --- | --- |
| 知识库创建者 | 管理知识库基本信息 | 需要重命名或删除已有知识库 | 在知识库列表页直接重命名；删除时得到二次确认，确认后删除 |
| 知识库创建者 | 删除知识库 | 确认不再需要某个知识库 | 仅创建者可执行删除，删除前必须二次确认，避免误删 |
| 知识管理员 | 管理知识库目录结构 | 需要按目录组织文档 | 在知识库页面右键创建目录，文档列表以树状结构展示目录层级 |

| 已登录用户 | 新增或编辑各类资源 | 需要创建知识库、上传文档、配置模型 | 统一使用页面中央弹窗完成，交互一致 |

## 业务规则

| 规则编号 | 规则内容 | 适用场景 | 例外或边界 |
| --- | --- | --- | --- |
| BR-001 | 导航只展示真实可用能力或明确的不可用状态（disabled 占位），不展示无对应功能的普通占位入口 | 全部导航 | 后续 feature 开放新能力时再新增对应入口 |
| BR-002 | 知识库删除必须二次确认，且仅知识库创建者可执行删除；非创建者不展示删除入口 | 知识库管理 | 重命名权限可放宽至管理员，删除权限严格限定创建者 |

## 业务流程

### 主要流程

1. 用户登录后通过顶部导航进入知识库列表页。
2. 在知识库列表页，用户可创建、重命名或删除知识库；删除需二次确认且仅创建者可执行。
3. 用户点击某个知识库进入知识库内部，进入文档工作台。
4. 在文档工作台，用户通过右键创建目录结构，文档列表以树状展示目录层级。
5. 用户上传文档（使用中央弹窗），选择是否解析，上传反馈在弹窗内清晰可见。
6. 用户进入文档详情，操作反馈归属到触发位置；异步任务局部刷新，不遮蔽整页。
7. 用户通过顶部导航进入模型设置，用单个中央弹窗表单完成模型配置（含高级参数）。
8. 前端先用演示数据走通上述交互，交互满意后切换为真实接口并优化后端。

### 异常或分支

- 删除知识库时，若用户非创建者，删除入口不展示或不可用。
- 删除知识库二次确认被取消时，不执行删除。
- 目录结构在换设备或清缓存后消失，上传文档后从文档路径自然聚合恢复。
- 演示数据与真实接口切换时，不污染真实数据；切换回真实接口后演示数据不残留。
- 操作失败时，失败反馈停留在触发操作附近，不替换整页内容。
- 异步任务刷新失败时，不影响现有展示，下次刷新自动重试。

- AC-012：Given 用户触发某个操作（如解析、发布、保存设置），when 操作进行中或完成，then 反馈停留在触发操作附近，不影响页面其他区域的独立交互，不出现整页冻结。关联需求：REQ-007。
- AC-013：Given 文档任务处于运行态，when 任务在后台刷新，then 只更新相关区域，不遮蔽整页；任务进入终态、用户离开页面或切换文档时刷新停止，不出现重叠请求。关联需求：REQ-008。
- AC-014：Given 用户查看知识库列表、文档列表或模型列表，when 数据呈现，then 根据数据量与字段特征选择合适的呈现模式（卡片、表格或列表），信息密度合理，页面元素丰富。关联需求：REQ-009。
- AC-015：Given 前端开发阶段，when 用户切换演示数据与真实接口，then 演示数据可走通全部交互，切换为真实接口后演示数据不残留、不污染真实数据。关联需求：REQ-010。
- AC-016：Given 用户切换亮色、暗色或跟随系统主题，when 主题切换，then 所有交互在三种主题下保持一致的信息层级和状态语义。关联需求：REQ-011。
- AC-019：Given 用户在 topbar 右侧点击主题切换按钮切换主题，when 切换完成，then 主题选择缓存到浏览器 localStorage；when 用户刷新或重新打开页面，then 主题沿用 localStorage 缓存值；个人偏好设置页面及其路由不再存在。关联需求：REQ-011、REQ-013。
- AC-017：Given 用户使用键盘操作，when 用户通过 Tab 和 Enter 完成主要操作，then 焦点路径合理可见，弹窗和菜单可键盘访问。关联需求：REQ-011。
- AC-018：Given 本次交互重设计完成，when 用户执行上传、解析、发布、重新分块操作，then 业务状态机和幂等语义与重设计前一致，不因交互变化改变业务结果。关联需求：REQ-012。
- AC-020：Given 用户点击文档进入详情页，when 文档源文件为图片/PDF/Markdown/TXT/DOCX，then 详情页左侧直接展示源文件内容（图片用图片组件、PDF 用 PDF 预览、Markdown 渲染为 HTML、TXT 纯文本、DOCX 用 mammoth.js 转 HTML）；不支持的格式提供下载链接。关联需求：REQ-014。
- AC-021：Given 文档已有分块结果，when 用户查看文档详情页，then 右侧并排展示分块详情（分块列表、分块内容、来源定位），与左侧源文件内容对照查看。关联需求：REQ-014。
- AC-022：Given 用户点击解析文档，when 解析任务处于排队或处理中，then 解析按钮禁用且显示实时进度条（有 progress 数据时）或"解析中"文案（无 progress 数据时），不出现重复触发。关联需求：REQ-015。
- AC-023：Given 文档解析失败，when 用户查看文档详情，then 显示失败原因且解析按钮可用，用户可再次发起解析，不因前次失败阻塞。关联需求：REQ-015。
- AC-024：Given 用户在文档列表页，when 用户勾选一个或多个文档并点击删除，then 弹出二次确认，确认后执行删除（前端 demo 模式即时移除，real 模式调后端删除接口）。关联需求：REQ-016。
- AC-025：Given 文档已发布到 RAG 知识，when 用户删除该文档，then 后端同步删除 ES 索引和解析结果，软删除文档记录（后端阶段执行，前端先用演示数据）。关联需求：REQ-016。

## 质量要求

- 性能：不适用，原因：本次为前端交互重设计，无特殊性能指标；异步任务刷新优化不得引入明显的性能回退。
- 安全：模型 API Key 延续已有规则（只替换不回显，取消或关闭时清理）；知识库删除权限严格限定创建者；演示数据与真实接口切换不污染真实数据。
- 兼容：不改变知识库文档生命周期的业务状态机；CR-014 目录结构方案不推翻；与已有 CR-015 一致性修复成果兼容。
- 可用性：三主题一致；键盘可访问；响应式（桌面与移动端）；操作反馈清晰归属；页面元素丰富度提升。

## 风险与待确认

### 风险

- **（CR-001 调整，2026-08-08）** 模型设置不再合并表，无后端迁移风险；但前端 ModelSettingsTab 约 80% 重写为 Ragflow 式左右双栏，若新交互存在明显缺陷需回滚，可恢复 T006/T011 的旧合并表单代码（Git 历史保留）。
- 7 模型类型枚举扩展后，知识库 kb_model_binding.usage_type 白名单若有遗漏会导致新类型无法绑定；需统一在常量文件中集中维护 7 枚举白名单并覆盖连接/档案/binding 三处。
- preferenceJson.defaultModels 子节点写入时，若后端直接整字段覆盖会导致用户其他偏好（如后续新增的语言/排序）丢失；需确认后端 PATCH /users/me 执行局部 JSON 合并而非整体覆盖。
- 知识库删除为不可逆操作，若权限判断或二次确认失效可能造成数据丢失；需严格验证创建者权限和确认流程。
- 前端先行用演示数据，若演示数据与真实接口行为偏差较大，切换时可能暴露交互缺陷；需保证演示数据忠实模拟真实接口行为。
- 导航模型从左侧轨道改为顶部导航，视觉变化大，需验证三主题和移动端响应式不回退。
- 存量 CHAT 值兼容：若应用层别名映射遗漏，旧数据模型会显示为空或无法绑定；需在读取 API 的 DTO 层统一处理 CHAT→LLM 别名。

### 假设

- CR-015 的前端交互基础组件成果可作为本次重设计的组件基座。
- 现有 V4 视觉 token 延续，不重塑视觉语言。
- 后端阶段会承接模型配置合并和知识库删除/重命名接口的设计与实现。
