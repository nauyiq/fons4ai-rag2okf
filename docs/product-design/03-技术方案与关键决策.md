# 技术方案与关键决策

## 1. 技术栈

| 能力 | 当前选择 |
|---|---|
| 主要语言 | Java |
| 应用框架 | Spring Boot / Fons4AI |
| RAG 编排 | LangChain4j |
| 关系数据库 | MySQL |
| 对象存储 | MinIO |
| 检索引擎 | Elasticsearch |
| ES Java 客户端 | `co.elastic.clients:elasticsearch-java` |
| 文档解析 | Tika + MinerU，使用显式 Parser Profile |
| LLM/Embedding/Reranker | 具体模型待评测后确定 |

已决定选择 Elasticsearch，不选择 OpenSearch。

框架层已从 Elasticsearch 7.17 和多客户端并存状态升级，移除 RHLC、Easy-ES 和无调用方旧抽象。Spring Boot 3.5.8 当前解析 Spring Data Elasticsearch 5.5.6 与官方 `elasticsearch-java` 8.18.8，模块上下文测试和 Reactor 构建已通过。知识库 TV-01 首轮使用 Elasticsearch 8.18.x 同 minor 服务端验证该基线；执行前应确保服务端 patch 不低于客户端 patch，优先精确对齐 8.18.8。9.x 跨 major 升级延后到 P1 或框架依赖再次升级时评估。

P0 坚持应用层 RRF。ES 内置 RRF 可以作为授权允许时的附加实验，但不作为作品运行的必需依赖。

## 2. 总体架构

```text
Web UI
  ↓
Knowledge Application Service
  ├── Document Service
  ├── Parsing Service
  ├── Publication Service
  ├── OKF Service
  ├── Retrieval Service
  └── Query Trace Service
        ↓
MySQL / MinIO / Elasticsearch / Model Services
```

Fons4AI 提供框架抽象和可插拔能力，LangChain4j 负责 Advanced RAG 编排，不让业务对象直接依赖某个向量库 SDK。

## 3. 存储边界

### MySQL：业务事实

- Workspace、KnowledgeBase 和配置；
- 文档、版本、解析任务和发布任务；
- PublicationRevision 与当前活动版本；
- OKF Bundle、Concept、Revision、Relation 和 Source Binding；
- AnswerEvidence、QueryTrace 摘要和用户反馈；
- Outbox、幂等键和任务状态。

### MinIO：不可变内容与大对象

- 原始文件；
- 解析完整结果和页面图片；
- Source Anchor Manifest；
- Chunk Manifest；
- OKF Markdown Bundle 与 ZIP；
- 大型 Query Trace 调试数据。

### Elasticsearch：可重建检索投影

- Parent/Child Chunk；
- Concept 文本与向量；
- 检索过滤字段；
- 简化后的来源定位字段。

## 4. 文档切分

默认采用结构感知的 Parent/Child 策略：

- Child 用于高精度召回；
- Parent 用于重排和回答上下文；
- FAQ 尽量保持原子性；
- 表格切分时重复表头；
- 同一 Parent 的多个 Child 命中后先去重再重排。

文本字段分离：

```text
rawText        解析得到的原始内容
embeddingText  用于向量化的增强文本
displayText    用于展示和引用的文本
```

## 5. Elasticsearch 索引

推荐独立投影：

```text
kb-chunk-v{n}
kb-okf-concept-v{n}
```

通过读写别名访问：

```text
kb-chunk-read / kb-chunk-write
kb-okf-concept-read / kb-okf-concept-write
```

模型、Mapping 或切分策略发生重大变化时建立新物理索引并切换别名。普通文档发布使用增量写入，不为每个文档创建独立索引。

## 6. 在线检索链路

```text
请求上下文与权限过滤
→ 条件式问题改写
→ 查询类型判断
→ BM25 TopK 与向量 TopK 并行召回
→ 应用层 RRF
→ Child 去重与 Parent 扩展
→ Cross-Encoder/Scoring Model 重排
→ 证据充分性判断
→ 上下文组装
→ 带引用生成
→ 引用合法性校验
```

建议初始候选值，仅作为评测起点：

```text
BM25 Top 30
Vector Top 30
RRF Top 20
Rerank Top 6-8
```

阈值和 TopK 必须通过评测集调整，不能作为固定真理。

## 7. Retrieval Profile

预置：

```text
BM25_BASELINE
VECTOR_BASELINE
HYBRID_RRF
HYBRID_RRF_RERANK
```

正式问答推荐 `HYBRID_RRF_RERANK`。每次 QueryTrace 记录 Profile 和版本。

## 8. 失败与降级

| 故障 | 处理 |
|---|---|
| Embedding 服务失败 | 退化为 BM25 |
| BM25 失败 | 退化为向量召回 |
| Reranker 失败 | 使用 RRF 结果 |
| LLM 生成失败 | 返回证据或明确失败，不生成无依据答案 |
| 引用校验失败 | 不返回未校验答案 |
| ES 整体不可用 | 明确提示知识检索不可用 |

所有降级必须写入 QueryTrace，不能静默发生。

## 9. Query Trace

记录：

- 原始问题与改写问题；
- 检索范围和权限过滤；
- BM25、向量、RRF 和重排结果；
- Parent/Child 展开；
- 最终上下文；
- 引用和校验结果；
- 模型与 Profile 版本；
- 各阶段耗时、错误和降级状态。

## 10. 明确不采用

- 向量库作为唯一事实来源；
- OKF 强绑定每次文档发布；
- MVP 引入 Neo4j；
- MVP 开放式 Agentic RAG 循环；
- LLM 直接写最终 OKF 文件；
- 解析失败后静默回退到另一个解析器；
- 多套 Elasticsearch Java Client 长期并存。
