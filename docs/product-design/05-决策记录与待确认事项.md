# 决策记录与待确认事项

## 1. 已确认决策

### 产品

- 项目是知识库与知识工程作品，不是简单聊天壳。
- 演示领域使用金融贷款知识。
- MVP 先实现知识管理员和知识用户两个角色。
- 业务方案和技术方案确认前不编码。

### 文档

- 上传、解析和发布解耦。
- 用户可以上传但不解析，此时只能查看和下载原文件。
- 知识库支持 `autoParse` 和 `autoPublish`。
- 默认自动解析、人工发布。
- ParseRevision 与 PublicationRevision 分离。
- 发布是 Saga/Outbox 可重试流水线。

### 存储与检索

- 使用 MySQL、MinIO 和 Elasticsearch。
- 选择 Elasticsearch，不选择 OpenSearch。
- 框架层统一官方 Elasticsearch Java Client。
- Parent/Child Chunk。
- BM25 + 向量 + 应用层 RRF + 重排。
- 使用版本化物理索引和别名。

### 回答与引用

- 证据不足时拒答。
- 回答需要引用本次使用的证据。
- 引用绑定历史 PublicationRevision，而不是文档最新版。
- PDF 优先实现页码和区域定位。
- 保存 Query Trace 和 AnswerEvidence。

### OKF

- OKF 属于某一个知识库。
- OKF 是知识库级派生知识层，与文档 RAG 发布解耦。
- 统一从 Parsed Document 提取。
- 大量文档逐文档提取，再做知识库级合并。
- LLM 只生成结构化候选，Java 渲染最终 OKF。
- 候选需要来源绑定和人工确认。
- 不引入 Neo4j。
- Concept 与 Chunk 分别建立检索投影。
- 最终回答引用原始文档。

### 视觉

- 采用 V4 Spatial AI Knowledge Workspace。
- 支持亮色、暗色和跟随系统。
- OKF 不出现在全局一级导航。
- V4 原型文件保存在 `prototypes/v4`。

## 3. 尚待确认的关键决策

### 产品与业务

- 产品最终名称和品牌；
- 是否采用“云帆普惠”及三个虚构贷款产品作为演示语料；
- 是否接受 16 个 SourceDocument、17 个 DocumentVersion 和当前事实字典；
- 全局知识问答是否进入 P0；
- OKF 人工确认是否允许批量确认；
- 撤回发布后是否自动回退到上一 PublicationRevision。

### 模型

- 主 LLM；
- Embedding 模型与维度；
- Reranker 模型；
- OKF 概念提取模型；
- 模型供应商切换和降级策略。

### Elasticsearch

- Fons4Cloud 客户端基线已确认：官方 `elasticsearch-java` 8.18.8；
- 待 TV-01 确认 Elasticsearch 8.18.x 服务端连接、API、插件和检索门禁，优先精确对齐 8.18.8；
- 9.x 跨 major 升级延期到 P1 或框架依赖再次升级时评估；
- 中文 Analyzer；
- 向量相似度算法和量化策略；
- 单索引多租户还是按规模拆分；
- 索引生命周期和容量基线。

### 文档解析

- Tika 与 MinerU 的明确适用类型；
- 扫描 PDF 是否进入 P0；
- DOCX 是否需要转换预览 PDF；
- 单文件大小、页数和超时限制；
- 表格与图片 OCR 的质量基线。

### OKF 审核

- Candidate 是否拆分 `ReviewStatus` 与 `ValidationStatus`；
- 是否要求所有候选完成裁决后才能发布；
- 高相似度重复项是否必须人工裁决；
- 批量确认是否只允许明确勾选且无阻塞的候选；
- 合并是否必须逐字段解决冲突。

### 评测

- 是否接受知识库内评测中心与全局检索实验室的职责划分；
- 是否接受首版 120 个金融黄金用例及 70% DEV / 30% TEST 划分；
- 是否接受解析、OKF、检索、回答引用、运行五层评测；
- 是否接受越权、错误版本、无效引用和 OKF 无来源为硬门禁；
- 解析、检索、回答和性能候选阈值需要经过技术验证校准。
