# 评测体系与金融黄金数据集

> 状态：候选方案，等待确认。本文中的质量阈值是首轮技术验证的起点，不是未经实测即可锁定的最终 SLA。

## 1. 评测目标

评测不是给整个 RAG 系统计算一个模糊的“总分”，而是回答三个具体问题：

1. 候选方案相对基线是否真的更好；
2. 改善或退化发生在解析、OKF、检索、回答还是引用阶段；
3. 该方案是否满足可发布门禁，并且能够在相同版本条件下复现。

评测中心属于某一个知识库。全局“检索实验室”用于临时调试单个问题，知识库内“评测中心”用于对固定数据集进行可重复的批量比较。

## 2. 核心原则

### 2.1 分层诊断，不使用单一总分

```text
源文件
  ↓
解析质量
  ↓
OKF 质量
  ↓
检索质量
  ↓
回答质量
  ↓
引用与运行质量
```

下游指标变差时，必须能够返回上游定位。例如答案错误不一定是 LLM 问题，也可能是解析丢表格、OKF 合并错误或正确证据没有进入 Top K。

### 2.2 确定性评测优先

- 文档 ID、版本、权限、SourceAnchor、引用是否存在等使用程序规则直接验证；
- 证据相关性使用人工标注的 Evidence Judgment；
- 语义忠实度、完整性等难以完全规则化的指标才使用 LLM Judge；
- LLM Judge 的模型、Prompt 和版本必须保存，并用人工小样本持续校准。

### 2.3 一次实验只比较一个主要变量

例如比较 `Hybrid RRF` 与 `Hybrid RRF + Rerank` 时，其余模型、索引和 Prompt 保持相同。否则即使结果改善，也无法知道是哪一项改动产生作用。

### 2.4 每次运行冻结依赖版本

每个 Evaluation Run 至少记录：

- `CorpusVersion`；
- `EvaluationDatasetVersion`；
- `IndexVersion`；
- `RetrievalProfileVersion`；
- `EmbeddingModelVersion`；
- `RerankerModelVersion`；
- `LLMVersion`；
- `PromptVersion`；
- `OKFBundleRevision`（该实验启用 OKF 时）。

## 3. 五层评测指标

### 3.1 解析层

| 指标 | 说明 | 评测方式 |
|---|---|---|
| Parse Success Rate | 支持文件中成功完成解析的比例 | 程序统计 |
| Text Coverage | 解析文本对人工基准内容的覆盖 | 字符/段落对齐 |
| Structure Accuracy | 标题、段落、列表和表格类型是否正确 | 人工标注样本 |
| Table Cell F1 | 表格单元格内容和行列关系 | 精确率、召回率、F1 |
| SourceAnchor Accuracy | 页码、区域、标题路径能否回到原文 | 确定性验证 + 抽检 |
| Reparse Rate | 因质量问题触发重解析的比例 | 运行统计 |

### 3.2 OKF 层

| 指标 | 说明 |
|---|---|
| Concept Precision / Recall / F1 | 应提取概念与实际提取概念的匹配程度 |
| Concept Type Accuracy | 产品、准入规则、材料、流程、术语等类型是否正确 |
| Relation Precision / Recall / F1 | 概念关系是否正确、完整 |
| Source Binding Validity | 每个发布概念是否绑定有效原文证据 |
| Merge Pair Precision / Recall | 跨文档去重与合并建议是否正确 |
| OKF Conformance Rate | Bundle 是否通过 OKF v0.2 兼容子集校验 |
| Human Acceptance / Edit / Reject Rate | 人工确认、修改和排除候选的比例 |

OKF 的召回率应按概念类型分别统计，避免数量多的“术语”掩盖数量少但重要的“准入规则”。

### 3.3 检索层

| 指标 | 诊断意义 |
|---|---|
| Recall@K | 正确证据是否被召回，是覆盖能力主指标 |
| MRR@K | 第一条正确证据出现得是否足够靠前 |
| nDCG@K | 多级相关证据的整体排序质量 |
| Precision@K / Context Precision | Top K 中无关噪声是否过多 |
| Parent Evidence Coverage | Child 命中后扩展的 Parent 是否覆盖完整证据 |
| Filter Correctness | 知识库、权限、状态和版本过滤是否正确 |
| Retrieval Latency P50 / P95 | 检索性能与尾延迟 |

固定比较四个 Retrieval Profile：

```text
BM25_BASELINE
VECTOR_BASELINE
HYBRID_RRF
HYBRID_RRF_RERANK
```

### 3.4 回答与引用层

| 指标 | 说明 |
|---|---|
| Faithfulness | 回答中的可验证陈述是否得到检索证据支持 |
| Factual Correctness | 回答与人工参考答案的事实一致性 |
| Response Relevance | 是否直接回答用户问题 |
| Claim Coverage | 必须回答的关键事实是否覆盖 |
| Citation ID Validity | 引用 ID 是否真实存在并属于本次检索上下文 |
| Citation Precision / Recall | 引用是否真正支持对应陈述、必要证据是否被引用 |
| SourceAnchor Resolution | 引用能否定位到历史 PublicationRevision 的原文 |
| Refusal Precision / Recall / F1 | 应拒答时是否拒答、有证据时是否错误拒答 |
| Forbidden Claim Rate | 是否出现黄金用例明确禁止的结论 |

### 3.5 运行层

- 批次成功率、失败率和重试率；
- Query Trace 完整率；
- 单用例 Token、模型费用和总成本；
- 检索及端到端 P50/P95 延迟；
- 降级策略触发率；
- 相同版本条件下的结果可复现率。

## 4. 金融黄金数据集

### 4.1 数据集定位

黄金数据集从属于一个知识库并进行版本管理。首批建议使用 12～20 份公开或合成的贷款产品、准入制度、申请材料、业务流程和术语文档，同时刻意加入 V1/V2 制度变化。

合成问题可以辅助扩充候选集，但只有经过人工确认的问题、证据和期望结论才能进入 Gold 标签。

### 4.2 首版规模与分布

首版建议 120 个用例：

| 类别 | 数量 | 示例意图 |
|---|---:|---|
| 精确事实与限额 | 30 | 年龄、期限、额度、比例 |
| 清单与材料 | 20 | 所需证件、申请材料 |
| 业务流程 | 15 | 贷前调查、审批顺序 |
| 多跳与关系 | 15 | 产品、规则、材料之间的组合条件 |
| 对比 | 10 | 两种产品或新旧制度差异 |
| 版本敏感 | 10 | 旧版规则是否仍然有效 |
| 多轮追问 | 10 | 省略上下文的后续问题 |
| 无答案与越界 | 10 | 文档没有依据或涉及真实授信决策 |
| **合计** | **120** |  |

数据集划分建议：

```text
DEV  70%：可用于调参和失败分析
TEST 30%：隐藏标签，发布前运行，不能参与调参
```

### 4.3 Evaluation Case 结构

```yaml
caseId: FIN-ELIGIBILITY-001
question: 经营贷借款人年龄上限是多少？
category: EXACT_FACT
difficulty: EASY
knowledgeBaseId: kb-finance-demo
corpusVersion: corpus-v3
expectedConceptIds:
  - eligibility-age-limit
expectedEvidence:
  - publicationRevisionId: pub-20260730-001
    sourceAnchor: page:8#region:age-rule
    relevanceGrade: 3
referenceAnswer: 借款人申请时年龄不超过 60 周岁。
requiredClaims:
  - max_age=60
forbiddenClaims:
  - max_age=65
shouldAnswer: true
rubric:
  requireCitation: true
  requireVersionMatch: true
```

对于拒答用例，需要额外记录 `expectedRefusalReason`；对于多答案问题，允许保存多组可接受的 Evidence 与 Claims。

## 5. 评测运行模型

### 5.1 核心对象

| 对象 | 职责 |
|---|---|
| EvaluationDataset | 某知识库的评测数据集逻辑身份 |
| EvaluationDatasetVersion | 一次不可变的数据集快照 |
| EvaluationCase | 问题、期望证据、答案约束和分类 |
| EvidenceJudgment | 文档证据与问题的人工相关性等级 |
| ConceptExpectation | OKF 概念和关系的期望结果 |
| EvaluationRun | 某次基线或候选方案的批量运行 |
| EvaluationResult | 单用例运行、阶段输出和失败原因 |
| MetricResult | 某层级指标及分组结果 |
| BaselineComparison | 基线、候选和差值 |

### 5.2 运行状态

```text
CREATED
→ RUNNING
→ SCORING
→ COMPLETED

异常：FAILED
人工中止：CANCELLED
```

每个用例保存 Parse/OKF/Retrieval/Answer/Citation 阶段的 Trace，以支持失败聚类，而不只保留最后的分数。

## 6. 候选质量门禁

以下数值用于首轮验证，需根据真实 Parser、模型和硬件结果校准：

| 层级 | 候选门禁 |
|---|---|
| 解析 | 支持格式成功率 ≥ 98%；SourceAnchor 正确率 ≥ 99% |
| OKF | 来源绑定有效率 = 100%；概念 Precision ≥ 0.90；Recall ≥ 0.80；类型准确率 ≥ 0.90；关系 Precision ≥ 0.85 |
| 检索 | Recall@20 ≥ 0.90；MRR@10 ≥ 0.75；权限/版本过滤正确率 = 100% |
| 回答 | Faithfulness ≥ 0.90；引用 ID 有效率 = 100%；引用 Precision ≥ 0.95；拒答 F1 ≥ 0.85 |
| 性能 | 检索 P95 < 1.5 秒；端到端 P95 < 8 秒，按目标硬件重新校准 |

以下属于硬门禁，任何一项失败都不能自动提升候选方案：

- 越权召回；
- 错误版本参与正式回答；
- 引用 ID 不存在或无法定位；
- 已发布 OKF 概念没有原文来源绑定。

## 7. LLM Judge 与人工校准

1. 首先使用 20～30 个用例建立人工评分校准集；
2. 保存 Judge 模型、Prompt、温度和评分原始输出；
3. 持续计算 Judge 与人工评分的一致性；
4. 两个候选回答做成对比较时，随机交换 A/B 顺序，降低位置偏差；
5. 低置信度、Judge 分歧和硬门禁失败进入人工复核；
6. Judge 只能辅助判断语义质量，不能覆盖确定性的权限、版本和引用校验。

## 8. 执行节奏

| 时机 | 数据集 | 用途 |
|---|---|---|
| 单次配置或 Prompt 变更 | 20 个 Smoke 用例 | 快速发现明显回归 |
| 每晚或人工触发 | 完整 120 用例 | 趋势与失败聚类 |
| 发布索引、模型、Prompt 或 Retrieval Profile 前 | 完整集 + 人工抽检 | 发布门禁 |
| 线上反馈回流 | 仅进入候选池 | 人工标注后才进入新数据集版本 |

## 9. 评测中心原型说明

评测中心位于：

```text
知识库 / 某个知识库 / 评测
```

页面采用 V4 Spatial AI Knowledge Workspace。它的标志性组件是“质量链路带”，将解析、OKF、检索、回答和引用串联起来，并直接展示候选相对基线的差值。下方通过指标对比、失败聚类和用例明细回答“为什么变好或变差”。

全局检索实验室继续保留，但不承担黄金数据集和发布门禁职责。

## 10. 参考依据

- [Elasticsearch Ranking Evaluation API](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-rank-eval)：支持使用人工评级文档计算 Precision、MRR、DCG、ERR 等排序指标。
- [Ragas available metrics](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/)：提供 Context Precision、Context Recall、Faithfulness、Factual Correctness 等 RAG 评测指标参考。
- [Ragas experimentation](https://docs.ragas.io/en/stable/concepts/experimentation/)：强调实验版本、元数据、单变量比较与结果保存。
- [ARES](https://arxiv.org/abs/2311.09476)：以少量人工标注校准 RAG 的上下文相关性、答案忠实度和答案相关性评测。
- [Judging the Judges](https://arxiv.org/abs/2605.06939) 与 [Position Bias of LLM-based Evaluators](https://arxiv.org/abs/2406.07791)：说明 LLM Judge 需要校准，并需控制成对评测中的位置偏差。
