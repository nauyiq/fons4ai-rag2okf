# 产品需求与 MVP 范围

## 1. 产品目标

建设一个以企业知识库为主、兼顾个人知识管理的知识工程平台。平台不仅提供文件上传和 RAG 问答，还要让用户看见知识如何被解析、发布、检索、引用和组织成 OKF Knowledge Bundle。

作品集需要体现以下能力：

- 文档工程：解析、结构保留、Parent/Child Chunk、版本与重试。
- RAG 工程：混合检索、RRF、重排、拒答、引用和可观察性。
- 知识工程：OKF 概念提取、关系、来源绑定、知识地图和开放导出。
- 企业能力：工作空间隔离、发布控制、历史版本和最小权限模型。

## 2. 演示业务领域

第一阶段使用合成或公开的金融贷款知识作为演示数据：

- 贷款产品说明；
- 借款人和企业准入政策；
- 申请材料清单；
- 贷前调查和授信审批流程；
- 术语定义与常见问题。

不使用真实客户隐私、真实征信数据或真实生产风控结果。

## 3. MVP 用户

### 知识管理员

- 创建和配置知识库；
- 上传、解析、预览、发布和撤回文档；
- 发起 OKF 构建并确认概念；
- 查看检索实验和 Query Trace；
- 管理知识库设置和反馈。

### 知识用户

- 选择知识库并提问；
- 查看答案引用和原文；
- 查看历史问答；
- 提交答案或引用反馈。

第一阶段不实现复杂组织架构、部门管理员、知识审核员和字段级权限。

## 4. 信息架构

```text
知识库平台
├── 知识库列表
│   └── 某个知识库
│       ├── 概览
│       ├── 文档
│       ├── OKF
│       │   ├── 知识地图
│       │   ├── 概念列表
│       │   ├── 构建记录
│       │   └── Bundle 版本
│       ├── 知识问答
│       ├── 评测
│       └── 设置
├── 全局知识问答（可选，多知识库范围）
└── 检索实验室
```

OKF 必须属于某个知识库。全局导航中不设置独立的“OKF 知识地图”。

评测中心也属于某个知识库，用于运行版本化黄金数据集和发布门禁；全局检索实验室只用于临时问题调试和检索参数探索。

## 5. 核心业务闭环

```text
创建知识库
→ 上传源文件
→ 选择是否解析
→ 检查解析结果
→ 发布 RAG 知识
→ 按需构建并发布 OKF
→ 知识问答
→ 查看引用和原文
→ 查看检索轨迹
```

## 6. 知识库配置

知识库创建时支持：

- `autoParse`：上传后自动解析；
- `autoPublish`：解析成功后自动发布 RAG 内容；
- 默认 Parser Profile；
- 默认 Chunk Profile；
- 默认 Retrieval Profile；
- 是否启用 OKF；
- 名称和描述。

企业知识库推荐默认：

```text
autoParse   = true
autoPublish = false
```

设置变化只影响未来上传。历史文档必须通过显式批量操作处理。

## 7. P0 MVP 范围

### 知识库与文档

- 最小 Workspace 与两个角色；
- 知识库创建、编辑和列表；
- PDF、DOCX、Markdown、TXT 上传；
- 原文件查看与下载；
- 自动/手动解析；
- 原文、解析结构和 Chunk 调试预览；
- 自动/手动发布；
- 撤回发布；
- 文档版本、解析版本和发布版本；
- 异步任务、失败原因与重试。

### RAG 与问答

- BM25 与向量双路召回；
- 应用层 RRF；
- Parent/Child Chunk；
-语义重排；
- 条件式问题改写；
- 证据不足拒答；
- 带引用回答；
- 原文定位；
- Query Trace；
- 检索实验室；
- 答案反馈。
- 知识库级评测数据集、基线对比和失败样本定位。

### OKF

- 知识库级 OKF Bundle；
- 从已解析文档构建；
- 金融概念类型模板；
- 概念候选、来源绑定和人工确认；
- 跨文档去重与合并建议；
- Concept Revision 与 Bundle Revision；
- 目录、列表和局部图谱；
- OKF v0.2 基础校验；
- Bundle ZIP 导出；
- Concept 检索与原文证据联动。

## 8. 延期范围

- 可信等级、新鲜度和冲突自动治理；
- Neo4j 或独立图数据库；
- 全局大规模图计算；
- Agentic RAG 自主循环；
- 多 Agent 与沙箱；
- 人工修改 Parsed Block；
- OCR 在线校正；
- 外部 OKF Bundle 导入；
- Git 双向同步；
- 网页、数据库和第三方系统连接器；
- 完整组织架构和细粒度 RBAC；
- 风控决策执行。

## 9. 视觉要求

- 采用 V4 Spatial AI Knowledge Workspace；
- 支持 `SYSTEM`、`LIGHT`、`DARK` 三种主题；
- 大画布展示知识关系，目录和详情采用上下文浮层；
- 主题切换不能只是颜色反转，亮暗主题分别定义语义 Token；
- 保持键盘可访问性、可见焦点和足够文本对比度；
- 所有 OKF 页面必须明确显示当前所属知识库。
