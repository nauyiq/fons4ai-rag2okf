# 样本文档内容规格与证据锚点

> 状态：候选方案，等待确认。本文定义 16 份虚构金融样本文档应当如何编写，但当前不生成正式 PDF、DOCX、Markdown 或 TXT 样本。

## 1. 目标与约束

本规格用于保证后续样本文档同时满足三类需求：

1. **业务一致性**：所有额度、期限、准入条件、材料和流程都来自已冻结的事实字典；
2. **技术可测性**：文档包含可控的标题、列表、表格、版本、跨文档链接和原文定位难点；
3. **评测可标注性**：每个黄金问题都能绑定稳定的语义锚点和明确证据等级。

所有文档必须显示：

```text
虚构演示材料，不代表任何真实金融机构或授信政策，不构成金融建议。
```

不得包含真实公司内部制度、真实客户信息、真实征信数据或生产系统截图。

## 2. 内容权威层级

该层级仅用于虚构演示语料的证据标注，不是完整的企业知识冲突治理方案。

```text
生效中的专项变更通知
  > 生效中的准入/管理规则
  > 生效中的产品说明与流程手册
  > 产品总览
  > FAQ 与术语解释
```

规则：

- 当前问答默认只使用活动 PublicationRevision；
- 历史问题必须显式指定日期或版本，才允许使用历史版本；
- FIN-015 只覆盖 FIN-004 中的年龄条款，不覆盖其他准入条件；
- FAQ 可以帮助召回，但不能覆盖制度文件；
- 产品总览只用于比较和导航，具体条件以专项规则为准；
- 两个同层级活动文档发生无法解释的冲突时，测试答案应拒绝自行裁决并展示冲突证据。

## 3. 通用文档元数据

PDF、DOCX 和 Markdown 使用相同的逻辑元数据：

| 字段 | 示例 | 说明 |
|---|---|---|
| documentId | `FIN-004` | SourceDocument 稳定编号 |
| title | 启航经营贷准入规则 | 文件显示标题 |
| version | `V2` | 文档版本 |
| status | `ACTIVE` | `ACTIVE` 或 `HISTORICAL` |
| issuedAt | `2026-03-15` | 虚构发布日期 |
| effectiveFrom | `2026-04-01` | 生效日期 |
| effectiveTo | `null` | 失效日期，当前版本为空 |
| supersedes | `FIN-004@V1` | 被替代版本 |
| owner | 产品制度组（虚构） | 内容责任角色 |
| classification | `PUBLIC_DEMO` | 仅公开演示数据 |
| language | `zh-CN` | 文档语言 |
| disclaimer | 虚构演示材料…… | 强制声明 |

PDF/DOCX 元数据同时写入文件属性；Markdown 使用 YAML Frontmatter；TXT 在文件头部使用 `key: value`。

### 4.3 表格编写要求

- 不能把关键表格保存为图片；
- 每张表必须有表名、表头和单位；
- 跨页表格重复表头；
- 合并单元格只用于分组，不能承载唯一关键事实；
- 金额同时写明单位，避免“200”被误解；
- 区间边界统一使用“不超过”“超过且不超过”等明确文本；
- 表格后增加一段文字解释，但不能引入与表格不同的新事实。

## 5. SourceAnchor 设计

### 5.1 语义锚点

设计阶段使用稳定语义路径，不把页码直接写进锚点 ID：

```text
{documentId}@{version}#{section}.{subsection}.{item}
```

示例：

```text
FIN-003@V2#product.amount
FIN-004@V2#eligibility.age
FIN-005@V1#materials.conditional.contracts
FIN-011@V1#approval-matrix.regional
```

### 5.2 解析后 Manifest

实际 SourceAnchor Manifest 建议包含：

```yaml
anchorId: FIN-004@V2#eligibility.age
documentId: FIN-004
documentVersionId: fin-004-v2
parseRevisionId: parse-fin-004-v2-r1
blockIds:
  - block-0042
sectionPath:
  - 准入条件
  - 借款人年龄
pageNumber: 3
bbox: [92, 218, 498, 286]
anchorPrecision: EXACT
excerptSnapshot: 申请日年龄应为23至58周岁，含边界。
excerptHash: sha256:pending
effectiveFrom: 2026-04-01
effectiveTo: null
```

页码、坐标、Block ID 和 Hash 必须由实际解析结果生成，不能在设计阶段伪造为最终值。

引用同时用于 Markdown 链接、OKF Relation 候选和跨文档检索测试。

## 8. Evidence Judgment 规则

| 等级 | 定义 | 示例 |
|---|---|---|
| 3 / Primary | 直接、完整回答问题的权威证据 | FIN-004 V2 的年龄条款 |
| 2 / Supporting | 支持解释或补充适用范围 | FIN-015 对年龄变更的说明 |
| 1 / Background | 有主题相关性但不能独立回答 | FIN-002 产品总览 |
| 0 / Irrelevant | 不应进入最终上下文 | 其他产品的无关规则 |

标注规则：

- 每个 Smoke Case 至少一个 Primary Evidence；
- 版本敏感问题允许多个 Primary Evidence 共同形成答案；
- FAQ 通常标为 Supporting，除非问题仅询问 FAQ 特有的非制度性说明；
- Historical 文档对当前规则问题标为 0，对明确历史问题可以标为 3；
- 证据相关性和答案正确性分开标注。

## 9. Authoring 与解析验收清单

### 文档生成前

- [ ] 所有事实已在事实字典登记；
- [ ] 文件编号、版本、生效日期和状态明确；
- [ ] 权威来源与摘要来源已经区分；
- [ ] 语义锚点没有重复；
- [ ] 跨文档链接目标存在。

### 文档生成后

- [ ] PDF 是文本型且字体嵌入；
- [ ] DOCX 使用 Heading、List 和 Table 样式；
- [ ] Markdown Frontmatter 可解析；
- [ ] TXT 分段和编号稳定；
- [ ] 文件元数据不包含真实公司或作者信息；
- [ ] 每页或每份文件包含虚构声明；
- [ ] 视觉阅读与纯文本抽取结果均人工检查。

### 解析后

- [ ] 所有黄金锚点能够映射到 Block；
- [ ] Primary Evidence 可以回到原文件；
- [ ] V1/V2 状态和生效日期正确；
- [ ] 表格边界没有改变规则含义；
- [ ] 20 个 Smoke 用例的证据 Manifest 完整。

## 10. 推荐生成顺序

```text
第一组：FIN-001、FIN-016
  先固定安全和回答边界

第二组：FIN-003～FIN-009
  固定三个产品及专项规则

第三组：FIN-010～FIN-013
  固定流程、权限、还款和术语

第四组：FIN-002、FIN-014
  根据权威文档生成摘要和 FAQ

第五组：FIN-004 V1/V2、FIN-015 联合复核
  验证历史版本和过渡安排
```

FIN-002 和 FIN-014 必须后生成，因为它们是其他权威文档的摘要，不能成为反向事实来源。

## 11. 下一确认门

进入实际样本文档生成前，需要确认：

1. 是否接受证据权威层级；
2. 是否接受语义锚点与解析后物理定位分离；
3. 是否接受各文件的格式、篇幅和章节蓝图；
4. 是否接受 FIN-002 与 FIN-014 后生成的依赖顺序；
5. 是否允许后续生成虚构演示文档内容；
6. 即使允许生成样本文档，也不代表允许开发产品功能或业务代码。
