## 1. 适配范围

- 领域职责：当前源文件管理、解析、分块、RAG 发布和文档处理任务治理。
- 适配对象类型：解析器类型、分块边界策略、分块层级策略。
- 公共标准流程依据：用户逐项确认、项目产品设计、知识库文档生命周期 SDD；现有代码仅为现状证据。
- 不得作为适配维度：文件扩展名、自动/手动触发方式、模型厂商。它们分别是能力校验、触发方式和协议配置，不改变公共业务流程。
- 不得作为标准流程的特定实现：Tika、LangChain4j、具体 MinerU API 版本、当前段落切分、未知 Profile 默认回退、BM25-only 静默降级。

## 3. 标准流程判定

| 结论 | 依据 | 适用范围 | 限制 |
| --- | --- | --- | --- |
| 两种解析器共享 DocumentParser→Normalizer→Validator→JSON→首次分块骨架 | 两种适配横向对比+用户确认 | 全部解析 | 解析器内部步骤不同 |
| 解析器失败不跨实现回退 | 用户明确确认 | Built-in/MinerU | 用户可显式创建新任务选择另一解析器 |
| 分块采用边界和层级两个正交维度 | 三种边界与两种层级横向对比+用户确认 | 全部分块 | 默认是 STRUCTURE+PARENT_CHILD |
| OpenAI-compatible 是首阶段协议而非模型厂商适配 | 用户确认 | 模型调用 | 厂商特有 API 未来另加协议适配或网关 |
| 文件扩展名不是适配对象 | 用户确认 | 上传 | 上传只接受双方共同支持能力；精确清单待验证 |
