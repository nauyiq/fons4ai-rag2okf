# 代码编写规范

> 适用范围：Rag2OKF 仓库新增代码及发生实质修改的相关代码
> 规则状态：已确认
> 更新日期：2026-08-13
> 依据来源：`AGENTS.md`、`.specify/rules/agent运行规则.md`、`.specify/rules/fons4cloud-接入约束.md`、用户域知识模型、项目构建配置及代表性源码

## 基本原则

- 默认使用中文注释、日志说明和交付文档；代码标识符使用语义清晰的英文。
- 修改前必须读取需求、领域知识、相关规则、调用链、测试和配置；不得根据类名、实体字段或单个实现猜测业务规则。
- 新增代码和发生实质修改的相关代码必须遵守本规范；历史代码渐进治理，不得以统一风格为由自动批量搬包、改名或重写。
- 优先保持业务边界、公共契约和数据语义稳定。重构默认不改变 HTTP 契约、错误码、状态含义、事务语义和数据结构。
- 优先复用已有代码、项目现有框架能力、公共组件和领域抽象；新增依赖、平行框架或重复基础能力必须先说明必要性并取得确认。
- Java 使用显式 `import` 和简单类名；禁止通配符 `import`，除同名冲突、生成代码或框架限制外禁止在代码中使用全限定类名。
- 密码、Token、API Key、连接串和内部凭证属于敏感信息，不得写入日志、异常消息、通用 DTO、缓存键、事件载荷或测试快照。

## 工具类与复用

- HTTP/RPC 统一返回使用 `com.fons.cloud.common.result.R`，不得新增平行返回包装体系。
- 通用错误码优先复用 `ResultCode`；领域错误使用项目业务错误码或领域异常，不得散落字符串错误码。
- 新增五个以上字段映射，或同类字段搬运重复出现时，优先复用既有转换方式或提取显式 Converter；适合时使用 MapStruct、`CommonConverter` 或等价模式。不使用转换器时应在实施报告中说明原因。
- 无 Bean 注入、无外部资源访问、无业务状态的纯函数能力才可放入 `common.util`。
- 依赖 Spring Bean、配置、数据库、Redis、MQ、文件、远程服务、模型 SDK 或领域状态的能力必须作为端口、领域能力或基础设施适配器，不得伪装成静态工具类。
- 字符串、集合、Map 和数组的常见操作优先复用项目已有 Apache Commons 或框架工具；同一模块不得无理由混用多套工具。
- Hutool 仅用于项目已有且适合的专项能力，不得用通用工具方法掩盖领域校验、状态迁移或异常处理。
- 鉴权、Token、锁、限流、文件和消息能力优先复用 Fons4Cloud 已接入组件，不得在业务模块另建平行实现。

## 代码风格

### Java 后端

- 使用 Java 21 语法但保持可读性；数据载体适合时使用 `record`，领域行为对象不得为了简短退化为无语义数据袋。
- 优先使用构造器注入和不可变依赖；禁止字段注入。配置项使用具名配置对象或明确的配置字段，并写明单位、默认值和安全边界。
- 方法保持单一职责，名称表达业务意图。复杂分支优先使用提前返回、领域行为或策略对象，避免多层嵌套和超长编排方法。
- 公共类型、接口、公共方法、Request、Response、配置对象、关键字段及非显而易见逻辑必须有注释。注释说明职责、语义、单位、不变量或边界，不机械复述代码。
- 安全、权限、Token、密钥、状态、时间、业务 ID、外部资源引用字段必须写明来源、用途、是否可变以及是否允许对外返回。
- 时间字段必须明确时间点还是持续时间；持续时间在名称或注释中写明单位。不得混用本地时间、UTC 和数据库时区而不说明转换边界。
- 领域状态使用枚举或值对象表达，禁止魔法字符串。权限覆盖必须使用显式动作或权限映射，禁止依赖枚举顺序和 `ordinal()`。
- Lombok 只减少样板代码，不得用全量 Setter 绕过实体行为和不变量；敏感字段必须排除在 `toString`、审计输出和调试快照之外。

### Vue 与 TypeScript 前端

- TypeScript 保持 `strict`，禁止用 `any`、非空断言或宽泛类型掩盖契约问题；确需未知输入时使用 `unknown` 并显式收窄。
- API 调用统一进入 `src/api`，统一处理响应包、认证头和错误；组件不得散落 `fetch`、拼接服务地址或自行解释后端错误包。
- 跨页面会话和 Workspace 状态使用 Pinia；局部交互状态保留在组件或 composable，避免所有状态全局化。
- 可复用的无界面逻辑提取为 composable 或纯函数；页面组件负责界面编排，不复制 API、权限和状态转换规则。
- 前后端字段、状态值和错误语义必须以确认的接口契约为准，不得在前端推断权限、伪造 `userKey`、角色或 Workspace 授权结果。
- Token 不得写入日志、错误上报或 UI；认证失效由统一 HTTP 层清理会话，并由 Store/Router 完成界面跳转。
- 组件、Store、API 类型和 composable 发生行为变化时补充对应 Vitest 测试；关键用户链路和跨页交互使用 Playwright 验证。

## DDD-lite 编码约束

统一采用：

> 声明式入口校验 + 行为型实体 + 同域聚合根 + 领域服务决策 + 应用层业务编排 + 基础设施技术运行编排。

### 分层职责

| 层次 | 负责 | 禁止承担 |
| --- | --- | --- |
| Controller/入口适配器 | 协议转换、声明式结构校验、Request 转 Command、调用应用用例 | 领域判断、事务、跨领域编排、直接访问 Mapper |
| Application | 用例顺序、跨领域端口协作、事务、幂等、补偿和失败协调 | 重复简单参数校验、直接构造 SQL、复制状态机、依赖具体技术客户端 |
| Entity | 初始化、自身行为、局部不变量和状态流转 | Bean 注入、持久化查询、事务、缓存、MQ、远程或模型调用 |
| Aggregate | 同域同一致性边界内的跨实体规则 | 包含其他领域可变实体、跨领域编排、外部调用、无限扩大边界 |
| Domain Service | 本领域复杂判断、实体查询协调、聚合装配与持久化协调 | 查询其他领域 Mapper、技术运行编排、重复实体规则 |
| Infrastructure | ORM、Sa-Token、Redis、MinIO、ES、模型 SDK、调度、重试和外部系统适配 | 决定业务状态是否合法、作出业务完成结论、编排跨领域业务顺序 |

### 依赖与领域对象

- 依赖方向遵循入口层调用 Application、Application 调用 Domain 和内部端口、Infrastructure 实现端口。业务层不得直接依赖 Mapper、MyBatis `Wrapper`、Redis 客户端、Sa-Token 静态工具或具体模型 SDK。
- 跨领域只传递业务标识、不可变 Snapshot、Context、Result 或领域事件；不得共享其他领域可变实体或直接访问其他领域 Mapper。
- 简单实体允许携带最小 MyBatis 表/字段映射注解；实体内部不得出现 Mapper、Wrapper、SQL、事务或基础设施调用。是否进一步拆分领域对象和持久化对象按复杂度决定，不作机械强制。
- 新增领域实体不使用 `Entity` 后缀；聚合根使用 `Aggregate` 后缀。历史类名仅在相关改造获批时迁移。
- 创建对象优先使用能维护合法初始状态的工厂方法、构造器或领域行为；不得在 Application 中通过一组 Setter 拼装复杂状态。
- Application 不直接向 Controller 返回持久化实体；通过 Response、View、Snapshot 或 Converter 输出安全字段。

### 用户域特定边界

- 登录注册链路作为代表性风格：Controller 精简、Request 转 Command、Application 顺序编排、实体工厂维护初始状态、注册事务显式覆盖 `LocalUser + Workspace + ADMIN WorkspaceMember`。
- 代表性风格不等于复制历史耦合。认证用例通过 `PasswordHasher`、会话、频控和账号 Repository 等端口协作，不直接调用静态安全工具或具体缓存客户端。
- 当前身份端口只提供身份标识，不携带全局业务角色；访问 Workspace 必须按目标空间和显式动作调用授权端口。
- Workspace 唯一所有者与成员角色分离；所有者高风险操作必须单独校验。禁止用角色枚举顺序表达权限高低。
- `WorkspaceInvitation` 和 `WorkspaceMember` 是不同生命周期对象；邀请功能未完成 SDD 前不得擅自实现表、API、状态迁移或通知机制。
- `ModelConnection`、`ModelProfile` 和加密凭证归用户域，`ModelBinding` 归知识库域。知识库域只能通过模型档案校验与能力解析端口协作，不得读取或解密 API Key。
- OpenAI-compatible 作为协议适配器存在，不得让具体协议、LangChain4j 类型或 Provider 错误进入领域模型和公共契约。

## API 接口设计

- HTTP 路由、字段、状态和错误码属于公共契约；未经确认不得在重构中改名、删除、改变类型或改变兼容语义。
- Request、Command、Response、Entity 各司其职，不得互相兼任。HTTP Request/Response 放在入口能力范围内，领域 Command、Snapshot 和内部端口进入所属领域或应用包。
- Controller 使用 `@Valid` 触发 Jakarta Validation；`PathVariable`、`RequestParam` 和方法级约束需要时配合 `@Validated`。
- 必填、长度、格式、范围、集合数量和嵌套结构由 Request 约束；纯结构性的跨字段规则可使用类级 Validator。
- 数据唯一性、当前身份、权限、幂等、外部状态、实体不变量和状态流转分别由 Application、Domain Service、Entity 或 Aggregate 处理，不得伪装成普通参数注解。
- Application 不重复编写已经由入口声明式校验覆盖的判空、长度和格式检查。
- 创建、修改和查询语义差异明显时拆分独立 Request；字段和约束高度一致时才考虑校验分组。
- 列表接口明确分页、排序、过滤和稳定顺序；批量接口明确部分失败还是整体回滚，不得由调用者猜测。
- 对外只使用业务 Key，不暴露数据库自增主键。Token、密码摘要、API Key 密文/nonce、内部错误和堆栈禁止进入 Response。
- API 兼容性变化、状态语义变化、权限变化和错误码变化必须进入 SDD 或变更流程，并补充契约测试。

## 异常与日志

- 可预期业务失败使用项目业务错误码、领域异常或框架业务异常；系统异常保留原始 cause。禁止裸抛 `RuntimeException`，禁止吞掉影响事务、一致性和安全的异常。
- Controller 不重复捕获已由统一异常端点处理的异常；异常到 HTTP 响应的映射保持集中一致。
- 日志记录业务标识、阶段、结果码和必要的排障上下文，不记录完整请求体或敏感字段。
- 邮箱、对象路径和第三方响应按需脱敏；Token、密码、密码摘要、API Key、Authorization 头、连接串、密文和 nonce 不得记录。
- 调用外部模型、解析器、存储或搜索系统时，向客户端返回安全化错误；Provider 原始错误仅在确认无敏感信息后进入受控诊断日志。
- 捕获异常后必须选择重新抛出、转为明确业务错误或执行可验证补偿；禁止仅打印日志后返回伪成功。
- 日志级别与语义一致：可恢复业务拒绝不使用 ERROR；影响一致性、任务终止或未知系统故障使用 ERROR 并保留 cause。

## 数据访问与事务

- MySQL 是业务事实源，MinIO 保存不可变内容，Elasticsearch 是可重建检索投影；不得把 ES 结果作为唯一业务事实。
- 数据访问必须通过所属领域 Mapper/Repository。Application 和 Controller 不得直接构造 MyBatis `Wrapper` 或 SQL。
- 查询成员关系、模型档案和知识库资源时必须携带完整租户/Workspace/所有权条件，禁止先查到任意关联对象再与目标资源拼装。
- 更新、删除和批量操作必须有明确条件及影响行数处理；涉及并发状态迁移时使用唯一约束、乐观锁、CAS、幂等键或受控分布式锁。
- 事务边界位于 Application 或明确事务服务。单事务内只承诺同一数据库一致性；跨数据库、Redis、MQ、MinIO、ES 和外部服务必须设计幂等、补偿、Outbox/Saga 或失败恢复。
- 事务异常不得被吞掉并转换为无法区分原因的伪成功；唯一键冲突、乐观锁失败和外部故障应映射为稳定且可测试的结果。
- 上传、解析、发布保持解耦；发布使用可重试、幂等的 Saga/Outbox 过程，不得简化成单次状态更新。
- 字段映射必须明确业务 ID、外部流水、状态、时间、金额或数量单位、敏感级别和可空语义。状态口径在数据库、Java、API 和前端之间保持一致。
- 敏感数据使用已确认的加密与脱敏方案；API Key 明文只允许在加密或受控调用的短生命周期内存在，不缓存、不回显、不进入事件。
- DDL 和迁移脚本必须包含中文脚本说明、表注释和字段注释；非唯一索引必须绑定明确查询、排序、关联、唯一性或审计场景，不按字段清单机械建索引。
- DDL 评审必须检查主键/业务键、唯一约束、租户或 Workspace 边界、状态与时间字段、敏感字段、索引依据、幂等/并发策略、兼容性和回滚说明。不得从 Java 实体反向猜测 DDL。

## 数据映射与安全

- 字段映射必须保持数据库、领域对象、Request、Response、事件和前端类型的名称、含义、可空性、枚举值及单位一致；任何语义转换必须集中在显式 Converter 或适配边界。
- 金额统一使用最小货币单位或明确精度的十进制类型，字段名和注释必须写明币种、单位、精度与舍入规则；禁止使用浮点类型表达金额。当前无金额业务时不得预设字段或规则实现。
- 日期和时间必须明确时区、精度、序列化格式及数据库含义；持续时间必须标明单位，禁止仅凭裸整数推断秒、毫秒或分钟。
- 外部流水号、业务 Key、数据库主键和第三方资源 ID 必须分开建模，禁止相互替代或将内部主键暴露为公共契约。
- 枚举持久化值和 API 值必须稳定且显式，禁止使用 `ordinal()` 持久化或表达业务优先级、权限和状态迁移。
- 新增五个以上字段的对象转换或重复映射使用 Converter；转换测试必须覆盖空值、枚举、时间、ID、敏感字段排除和兼容默认值。
- 敏感数据按最小暴露原则处理：密码只保存不可逆摘要；Token 不持久化到业务库；API Key 使用已确认的加密方案，明文仅在受控短生命周期内存在。
- 日志、错误响应、指标标签、事件、缓存键和测试快照都必须执行敏感数据审查；邮箱和外部路径按场景脱敏，密码、Token、API Key、连接串、密文和 nonce 禁止输出。
- 权限校验使用服务端当前身份和受控资源上下文，不信任客户端传入的用户、角色、所有者或授权结论；跨 Workspace 数据访问必须包含完整隔离条件。
- 数据变更需要审计时，记录操作者业务标识、目标业务标识、动作、结果和时间，不记录秘密原值；高风险凭证操作只记录替换或删除事实。

## 测试与验证

- 新增业务行为、公共契约、状态机、安全权限、缓存、数据库、外部调用、限流、事务、Saga/Outbox 和并发控制必须先建立失败测试或可复现的 RED 证据，再实现通过。
- 纯包结构、模块骨架、文档和 DDL 草案可使用编译、自检或评审清单作为等价验证；环境失败和编译失败不能冒充业务 RED。
- 单元测试覆盖实体不变量、状态流转、领域策略和纯转换；应用测试覆盖用例顺序、事务、幂等、失败补偿和端口协作；集成测试覆盖 ORM、Redis、Sa-Token、MinIO、ES 和模型适配器边界。
- 认证与注册至少覆盖邮箱规范化、统一认证错误、失败频控、事务回滚、注册后会话及敏感信息不泄露。
- Workspace 授权至少覆盖账号/空间/成员状态、目标 Workspace 限定、所有者高风险动作、ADMIN/KNOWLEDGE_USER 显式权限和跨空间越权。
- 模型资源至少覆盖所有权、凭证不回显、加密轮换、端点安全、协议适配、测试失败安全化及知识库域不能解密凭证。
- 前端修改至少执行相关 Vitest；公共 API、Store、Router、核心页面或用户主链路变化补充 Playwright。TypeScript 修改必须通过 `typecheck`。
- 后端修改至少执行相关 JUnit 测试和模块编译；涉及启动配置或集成链路时补充应用启动、健康检查和核心接口验证。
- 测试使用隔离数据库/schema、MinIO 前缀和 ES 索引前缀，只清理本次测试创建的数据。
- 完成声明必须提供新鲜 Evidence Bundle：执行命令、退出码、关键结果、未执行项、环境限制、Spec Review、Code Review 和人工 Gate 状态。实现 Agent 的自检不能替代独立裁判。

## 禁止事项

- 禁止未确认业务方案和技术方案就编码，禁止超出当前 SDD、变更单或用户授权范围。
- 禁止让 Controller 编排业务、Application 直接操作 Mapper/技术客户端、Infrastructure 决定业务状态、Entity 调用外部系统。
- 禁止跨领域查询 Mapper、共享其他领域可变实体或绕过内部端口直接读取敏感数据。
- 禁止将 Request、Response、DTO、VO 直接作为持久化实体，禁止向外返回持久化实体。
- 禁止通过 Setter 绕过实体行为，禁止把状态机、权限策略和事务逻辑堆入工具类。
- 禁止使用枚举顺序表达权限，禁止信任客户端传入的 userKey、role、owner 或 Workspace 授权结论。
- 禁止记录、提交或回显密码、Token、API Key、连接串、真实账号及其他敏感数据。
- 禁止吞异常、伪造成功、忽略更新行数、无条件更新/删除以及缺少租户或 Workspace 条件的数据访问。
- 禁止把 Elasticsearch 作为唯一事实来源，禁止把上传、解析、发布合并为单一文档状态。
- 禁止无验证证据声称完成，禁止用环境错误代替业务测试，禁止实现 Agent 自行作最终验收结论。
- 禁止为了形式统一一次性迁移全部存量代码；大范围重构、删除文件、公共契约变化和数据库结构变化必须先确认。
