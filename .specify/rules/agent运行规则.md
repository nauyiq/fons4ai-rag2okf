# Agent运行规则

> 适用范围：Rag2OKF 仓库（`fons4ai-rag2okf/`）
> 知识状态：基线已建立
> 更新日期：2026-08-13

## 项目适用范围

- 仓库包含两个独立构建项目：`fons4ai-rag2okf-service/`（Java 21 + Spring Boot 3.5.8 Maven 后端）和 `fons4ai-rag2okf-ui/`（Vue 3 + TypeScript + Vite 前端）。
- 仓库根目录不是 Maven Reactor 或 Node Workspace，不得生成聚合 `pom.xml` 或根 `package.json`。
- SDD 产物位于 `spec/features/<yyyymmdd>/`，知识库位于 `.specify/memory/`，规则位于 `.specify/rules/`。
- 本规则适用于在本仓库内工作的所有 AI Agent。

## 核心原则

1. **默认中文**：沟通、文档和交付说明使用中文；代码注释遵循同一规则。
2. **先读后改**：修改代码前必须先理解需求，必须先读取相关上下文；不得在未读取文件的情况下提议修改。
3. **事实为本**：不得猜测业务逻辑、编造接口、编造数据库字段、编造第三方 API；用户提供文档与源码不一致时，必须标记冲突并请求确认。
4. **复用优先**：优先复用已有代码，优先使用项目已有的工具函数、组件和依赖；不重复造轮子。
5. **优先遵循项目规范**：遵循 AGENTS.md、知识库和技术设计中的口径与约束。
6. **显式 import**：Java 代码优先通过显式 `import` 引入类型并使用简单类名；除同名类型冲突或框架限制外，不得使用通配符 `import` 或全限定类名。
7. **确认后再动**：删除文件、覆盖文档、大范围重构、修改数据库结构前必须确认；业务方案和技术方案确认前不编码。
8. **DDD-lite 分层**：后端按 `controller` → `application` → `domain` → `infrastructure` 分层；领域对象不依赖 MyBatis、MinIO、Elasticsearch 或 LangChain4j 类型，这些依赖只出现在基础设施适配器。
9. **安全硬约束**：密码明文禁止日志/持久化/回显；API Key 明文仅短暂存在于请求/调用内存；日志不记录完整邮箱、token、Authorization 头和第三方完整错误。
10. **增量治理存量代码**：新规则默认约束新增代码和发生实质修改的相关代码；未经用户确认，不得据此批量搬包、重写持久化实体或迁移全部存量代码。

## 用户域执行边界

- 用户域规则以 `.specify/memory/domains/user/` 为事实来源；项目级旧文档与该领域文档冲突时，必须先标记冲突，不得沿用旧边界继续实现。
- `LocalUser`、`Workspace`、`WorkspaceMember`、`WorkspaceInvitation`、`ModelConnection` 和 `ModelProfile` 归用户域；`ModelBinding` 归知识库域。下游域只能引用用户域标识并通过内部端口请求身份、授权、模型档案校验或模型能力解析。
- 邮箱密码是当前唯一认证标准。登录成功只证明当前身份，不授予任何全局业务角色；访问 Workspace 资源必须重新校验账号、空间、成员关系及目标动作。
- Workspace 有唯一所有者；所有者同时具有 ADMIN 成员角色，但删除、移交等高风险动作必须显式校验所有权。角色覆盖必须使用显式权限或动作映射，禁止依赖枚举声明顺序或 `ordinal()`。
- `WorkspaceInvitation` 与 `WorkspaceMember` 必须分离，只有邀请接受成功后才能创建生效成员关系。邀请接口、唯一键、并发接受、超时和通知机制尚未完成 SDD，本规则不得被视为邀请功能的实现授权。
- `ModelConnection` 和 `ModelProfile` 的所有权、凭证与协议适配由用户域管理；知识库域不得读取或解密 API Key，不得直接查询用户域持久化实现，只能通过 `ModelProfileValidationPort`、`ModelCapabilityResolutionPort` 或等价内部契约协作。
- OpenAI-compatible 只是当前代表性协议适配，不得写成用户域唯一模型协议或不可替换的领域规则。

## 用户域后端改造门禁

- 登录注册链路是用户域后端的代表性代码风格：Controller 保持精简，外部 Request 转为用例 Command，Application Service 按业务步骤编排，领域对象通过行为方法或工厂维护初始化与不变量，事务边界必须显式且可验证。
- 代表性风格不等于允许复制现有耦合。新增或实质修改的 Application Service 不得直接依赖 MyBatis `Mapper`、`Wrapper`、Redis 客户端、Sa-Token 静态工具或具体模型 SDK；应依赖 Repository、身份、会话、频控、加密和协议端口。
- 用户域优化按“行为回归测试与缺口修复 → 端口和依赖方向收敛 → 应用服务拆分 → 包结构和持久化模型清理”渐进执行。大范围搬包、实体与持久化对象完全拆分或公共契约调整必须另行确认。
- 认证、注册、Workspace 授权、凭证处理和跨域模型能力属于高风险链路；修改前必须建立对应特征测试或失败测试，至少覆盖事务回滚、统一认证错误、越权拒绝、显式权限、敏感信息不回显和跨域端口边界。
- 外部入口的必填、格式、长度和字段一致性优先使用 Jakarta Validation 或入口适配；依赖账号状态、数据唯一性、权限、事务、幂等和领域状态的校验必须留在应用或领域层，不得伪装为普通参数注解。
- `common` 只承载稳定、无领域归属的共享契约或纯工具。用户身份、Workspace、模型资源的 Request、Command、Response、状态、策略和端口应进入所属用户域能力包，不得继续无边界堆入 `common`。

## 实现者与裁判分离

- 实现 Agent 可以自检代码质量和测试结果，但不能作为最终裁判。
- Spec Reviewer 负责确认实现是否符合需求、设计和任务 AC，是否漏做、多做或偏离范围。
- Code Reviewer 负责确认代码质量、边界条件、异常处理、安全、兼容性和测试证据是否可接受。
- 没有独立 Spec Reviewer、Code Reviewer 或人工 Gate 证据时，只能标记为"实现候选完成"，不得声称可交付完成。
- 涉及权限、安全、密码、API Key、数据结构、生产配置或外部系统写入的任务，必须记录人工 Gate 状态；未通过时不得声明完成。

## 验证门禁

- 任务完成状态必须有新鲜验证证据（L3 验证证据：测试结果、构建结果或手工验证记录）；没有验证结果不得勾选完成。
- 环境失败、依赖下载失败或编译失败不能替代业务 RED 测试。
- 涉及 DDL 的任务，必须有执行型 DDL 草案或执行状态确认；DDL 未执行前，依赖结构变更的代码任务不得标记为发布就绪。
- 涉及独立可运行服务的任务，必须具备启动、健康检查和核心链路证据。
- 测试使用隔离数据库/schema、MinIO 前缀和 ES 索引前缀；集成测试结束只清理本次测试前缀。

## MCP与外部工具使用规则

- 项目当前无项目级 MCP 配置文件；不得编造 MCP 工具名称、数据库、账号、环境或连接方式。
- 个人本机 MCP 只能作为当前会话工具能力，不得写成项目规则。
- 使用 MCP 工具查询数据库时，只执行只读查询；不得执行 DDL、DML或生产数据修改。
- MCP 工具返回的敏感内容（密钥、token、连接串、内部地址）不得写入文件、日志或规则。

## 输出要求

- SDD 产物默认位于 `spec/features/<yyyymmdd>/`，核心文件为 `<功能中文名>-需求说明书.md`、`<功能中文名>-技术设计说明书.md`、`<功能中文名>-任务规划.md`。
- SDD 只使用 `S1` 和 `S2` 等级；全新需求优先使用 `fons4ai-sdd-feature-workflow` 编排。
- 生成任务规划或 CR 增量任务后必须暂停，等待用户确认执行。
- 用户回复 `执行`、`开始实现`、`继续执行` 时默认执行全部未完成任务；用户回复 `执行 T001,T002` 时只执行指定任务。
- 实施报告位于 `spec/features/<yyyymmdd>/reports/<功能中文名>-实施报告.md`，必须记录 Evidence Bundle、验证结果、DDL 状态、Review 状态和剩余风险。
- 代码新增公共类型、接口方法、请求/响应对象和关键字段必须补充简洁注释；安全、权限、Token、密钥、状态、时间、ID 字段必须写明语义和边界。

## 禁止事项

- 不得在仓库根目录生成聚合 `pom.xml` 或根 `package.json`。
- 不得从 Java 实体类反向猜测或生成 DDL；DDL 以技术设计表清单和手工初始化 SQL 为准。
- 不得把 Elasticsearch 作为唯一事实来源；MySQL 是业务事实源，ES 是可重建投影。
- 不得合并上传、解析、发布为单一"文档状态"；三者解耦。
- 不得在日志、DTO、异常或 Outbox 中携带密码明文、密码摘要、API Key 明文或 token。
- 不得信任浏览器传入的 userKey、role 或 workspaceKey 作为授权依据。
- 不得跳过 UI 设计确认 Gate 直接实现页面类交付物。
- 不允许修改与当前需求无关的代码、配置或文档。
- 不允许引入新的技术框架或依赖，除非技术设计说明书或用户确认中已说明原因。
- 不允许删除核心业务逻辑，除非用户明确要求。
- 不允许修改数据库结构，除非任务规划中已包含对应 DDL 工作项并经用户确认。
- 不得在未确认实现授权时开始编码。

## 信息不足时的处理

- 关键需求含义、业务术语、数据语义、验收口径、安全权限或兼容性存在歧义时，必须先澄清，不得直接生成正式 SDD 三件套或编码。
- Elasticsearch、模型和解析器等具体版本在验证前不得提前锁死。
- 单个实现方、渠道、策略或流程不得被写成标准流程，除非经过横向对比或用户确认。
- 无法确认的事实标记为 `待确认`，不得写成已验证知识或规则。
